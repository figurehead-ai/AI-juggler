# 0.4 completion

0.4.0 reached beta (2026-11-06) without its whole scope (D-83). This page
is the audit of every task the roadmap's 0.4 section names, requirement by
requirement against the code, and the order the rest is built in. It ships
as 0.4.x from `release/0.4.1`, with the maintainer's test findings, before
any 0.5 feature work.

`python3 scripts/release_scope.py report 0.4` is the live count. A task
counts only when its header says DONE and its evidence manifest has a PASS
line for every numbered requirement; release PRs, the nightly of a new
minor and every promotion fail otherwise.

**Audit, 2026-11-06:** 130 tasks named; 0 proven (34 marked done, none
with a PASS line per requirement); 96 open. Below, what each still needs.
"Evidence" means the manifest with a PASS line per requirement.

## Order

1. **Security and the architecture under it (E20).** 0.4 is the release
   that makes AI Juggler safe to recommend; nothing is promoted before it.
2. **The requirement gaps in shipped features** (E19, E21, E28, E29, E30,
   E31, E32, E35), smallest first within each.
3. **Validation by use and the evidence** (E33, E35's walks and gallery,
   a manifest for every task), on the replica and the throwaway lab.
4. **The maintainer's steps** (bottom), asked for once each, exactly.

## Maintainer finding #1 (0.4.0): starting and restarting apps, D-84

Fixed in commit f65f560b4 on `release/0.4.1`, for 0.4.1.

What was wrong:

- A closed Claude app profile's rail header found its app only by a
  running pid, so it had no Start, Restart or Keep alive.
- Its ended sessions were filed under the Claude Code folder App.
- A reused pid could read a closed app as running.
- Every app seen running was added as an App, which is how Inactive apps
  filled with apps the user never added and a leaked test profile.

**Live walk, 2026-11-06** (`tests/aij_test_live.rs`, run by hand on the
sanctioned aij-test profile, through the production code; no other
profile was started or quit):

| Path | Result |
| --- | --- |
| Open on the closed profile | Answered in 40 ms ("Starting Claude app · aij-test"); its main process was up at once |
| Seen running by an AI Juggler that never added it (D-84) | Only an offer, beside the user's other running apps (6 more offers); Open and Keep alive refused it; no desktop App was added |
| Open on it running | Brought forward in 1.0 s; no second copy |
| Confirmed Restart | Answered in 3.6 s, with one copy running again; the old pid no longer counts as the app (same program and start time checked) |
| Keep alive, after a quit as ⌘Q | Running again 7.3 s after the quit |
| End of the walk | aij-test closed again, as found |

**Tests:**

- Rust: `places::d84_tests`. Covers: an offer is not an App; Add and
  Not now; a gone folder forgets the offer; a temporary-folder profile is
  never recorded; a reused pid; a session started in a closed profile
  belongs to that profile.
- Migration: `juggler-core/tests/apps_v47.rs` (temporary rows dropped,
  first-seen bounded by the imported folder, `added`).
- vitest:
  - `rail-group-app.test.ts`: the header starts a closed app.
  - `rail-idle-app.test.tsx`: Restart… in Inactive apps.
  - `keep-alive.test.tsx`: Found on this Mac, with Add and Not now.
  - `rail-apps.test.ts`: attribution.

**Leaked fixture:**

- The "Lab Claude profile" came from the hand-run `places_real` walk:
  the installed AI Juggler saw its throwaway profile running and
  recorded it.
- The scan now skips the system's temporary folder.
- v47 removes the leaked row.
- `scripts/leaked_fixtures.sh` fails if a lab desktop profile outlives a
  run.

**Not yet done:**

- Clicking each door by hand in the AI Juggler Dev window: the rail
  header and its menu, Inactive apps, the App page, Home, ⌘K, Settings ›
  Desktop apps and "Open in" on an ended session.
- A fresh Dev build asks macOS for its own keychain item on every
  read. That needs the maintainer's Allow, which these walks never
  give, so the click-through waits for it.
