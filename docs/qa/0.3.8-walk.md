# 0.3.8: an app that lost its window, walked and scored

On 2026-11-04 at 01:59, macOS's watchdog ended `WindowServer` and the login session started again. Five Claude profile processes ran on with no window: `lsappinfo` didn't list them, and both the maintainer's launcher and AI Juggler's Open found their pids and started nothing. This page records the walk of the fix: the real system with a throwaway profile, then each new control in the window.

**Scores.** 1 to 5 for works, speed, clarity and layout. Anything under 4 is fixed before release.

## How "lost" is told, checked on this Mac

`juggler_platform::apps::detached` needs both facts: the process isn't an app macOS knows (`NSRunningApplication` by pid), **and** it started before this login session. Checked by hand, read-only, on 2026-11-04:

- `WindowServer` runs as `_windowserver`, and the process table gives no start time for it (sysinfo reads 0). The user's own `loginwindow` restarted in the same second (01:59:05) and its start is readable (its effective user is the person logged in; its real user is root). So the session's start is `loginwindow`'s.
- The maintainer's six Claude processes, started after 05:13, all read registered, so not lost, even when given a start time of 1.

## On the real system (a throwaway Claude profile)

`cargo test -p juggler-app --test places_real -- --ignored --nocapture --test-threads=1`, run 2026-11-04 on the maintainer's Mac. Claude starts with a new profile folder in a temp directory, never signed in. A real window-server restart can't be made without ending the user's login session, so `LostLab` scripts only the "lost" answer for the lab's own pid. The quit is a real SIGTERM to that lab process; the start is the real `open -n`. The maintainer's six Claude processes had the same pids and start times before and after. Every lab process was ended before its folder was removed.

## Combinations, and what covers each

| | Covered by |
|---|---|
| Lost: registered or not, older or younger than the session, either unreadable | `apps::tests::only_an_app_older_than_its_session_counts_as_lost`, `a_process_started_in_this_session_is_never_lost` |
| Entry: Open, Go to it, a place's Open (Home, rail, Settings, an ended session's Open in) | `an_app_that_lost_its_window_offers_a_restart_of_that_place`, `open_on_a_profile_that_lost_its_window_asks_to_restart_it`, `keep-alive.test.tsx`; every caller goes through `showGoTo` |
| Not a desktop app (a terminal) | never offered a restart (`an_app_that_lost_its_window_offers_a_restart_of_that_place`) |
| Restart: quits then starts, keeps the tool folder, won't quit, has its window | `restart_quits_the_lost_process_then_starts_it_as_it_ran`, `a_restarted_profile_keeps_its_tool_folder`, `restart_never_starts_beside_one_that_stays_or_quits_one_that_has_its_window` |
| Keep alive: restarts once behind; locked; a session working in it | `keep_alive_restarts_a_place_that_lost_its_window_once`, `keep_alive_leaves_a_lost_place_while_locked_or_while_a_session_works_in_it`; the 3-in-10-minutes, settling and quitting limits are keep alive's own (`keep::tests`) |
| A switch to Desktop | `a_profile_that_lost_its_window_is_never_sent_the_session_or_started_beside` |

**Not walked, and why.** A real window-server restart: it ends the user's login session and every app in it. The two facts it changes are each read on the real system above, and the rest of the path is real.
