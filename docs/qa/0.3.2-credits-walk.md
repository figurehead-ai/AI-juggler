# 0.3.2: a hand walk of "an account on its credits"

The maintainer's report: "Codex has run out of room · 0% of its weekly window left" while the Codex session kept working on pre-bought credits. This walk covers every surface the fix touched. It ran on 2026-10-30 in the vite preview of the fix's checkout, port 5199, seeded with:

- **Credits.** Codex: week used up, credits `{has_credits: true, balance: "14150.16"}`. Work Max: 70% left. Personal: 0% left, no credits. Fake Desk: not measured.
- **Zero.** The same, with Codex's balance at `"0"`.
- **Limit.** Work Max at 0% too, so the limit dialog's best target is Codex on its credits.

## What was fixed during the walk

- **New session (clarity 3 → 5).** The pick's line repeated "Codex: Using credits · 14,150 left" right under the same words on the pick's own line. It now gives only the consequence.

## Notes, not scored as this fix

- **Launch sheet.** Launching from New session a second time in the preview left the sheet open. The same happens for Work Max, an account with room, so it comes from the preview's launch stand-in, not from this fix. The launch was called with the right settings each time.
- **Limit dialog dates.** "Its window has reset" and the 2024 park date come from the preview fixture's session reading, which is a fixed old date.
- **Banner actions.** Continue on another account… / Open its account, Queue for the reset and Snooze 1 h on the zero-balance banner are unchanged. The banner band is being reworked separately.
