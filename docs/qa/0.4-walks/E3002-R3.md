# E3002 R3: OpenCode and Grok Build take the agent tools per launch (live) — walk sheet

AJ-E3002 R3 asks whether OpenCode and Grok Build load AI Juggler's agent tools for one launch with no prompt. The lab without sign-in (`docs/qa/pools-lab.md` §3) found that:
- OpenCode loads them from `OPENCODE_CONFIG_CONTENT`;
- Grok loads them from a `[mcp_servers]` entry in the `GROK_HOME` AI Juggler owns, but not from its `GROK_CONFIG` overlay.

This sheet proves it live on the release candidate, with a signed-in test account of each. The same run covers the parts of AJ-E1612's live checklist that one account each allows, and AJ-E3006 R3 ("does what its shell allows", now with tools).

- **Validates:** AJ-E3002 R3, AJ-E3006 R3; AJ-E1612 (found, start, resume, usage) for OpenCode and Grok Build
- **Runs on:** rc17 (AI Juggler Dev edition), real HOME, under condition 7b (`7b-live-claude.md`, whose fixed facts all apply here)
- **Build / walked by / on:** — (filled in by the walk)

Pass: every step does what it promised; nothing under 4; feedback ≤ 100 ms; nothing cut off or overlapping. A failure is a finding fixed in 0.4.1, and the steps after it are walked again.

## Who does what

- **Driver: sonnet**, by the RC's pid only (never ⌘⇧M, never the installed AI Juggler).
- **Checker: Opus**: every FAIL, and every PASS that closes a requirement, against the expectation and the capture.
- **The maintainer** does only the credential step in each sign-in window that AI Juggler opens (`opencode auth login`, `grok login`). The driver opens the window, then stops and tells the main session which window it is and what to type.

## The fixed facts

- **Their own tools.** OpenCode 1.19.5 (`/opt/homebrew/bin/opencode`) and Grok Build 1.0.77 (`~/.grok/bin/grok`) are the maintainer's own installs.
  - Never read, write or open the maintainer's own homes: `~/.grok`, `~/.local/share/opencode`, `~/.config/opencode`, `~/.local/state/opencode`. They are checked only by path, size and time (Before 1 and After 2).
  - Each test account lives in a folder AI Juggler makes for it: Add account creates a new App, never Import.
- **The project:** `~/lab/r3-tools`, made empty with `git init` at the start and removed at the end.
- **Harmless prompts only:** `ls`; `echo lab`; "write the word lab to lab.txt"; "list the tools you have from the juggler server"; and the pool's own tools (`whoami`, `pool_roster`, `send_message`, `read_inbox`, `task_claim`). Nothing else.
- **The Lab App** (Claude Code, `claude-code-361780292000`) is the pool's Lead, with `ENABLE_CLAUDEAI_MCP_SERVERS=false` as in 7b.
