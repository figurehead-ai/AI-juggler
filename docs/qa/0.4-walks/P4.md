## Findings

Found on the live run (2026-11-05), fixed in the commit that adds this sheet:

1. **AJ-E3006 / the lab.** Agents had no pool tools: nobody had answered the pool page's own "Let agents … work together?" question in the lab. Its answer is on the lab write mode's list now; with it, Codex got `whoami`, `pool_roster`, `send_message` and `share_doc`.
2. **The seeder.** It makes a pool "as the template would" but leaves the template's talk grid out, so member to member was allowed in Review and the first two messages went through. The rule was set as the wizard sets it (`role:member` → `role:member` blocked); the seeder still says so in its notes.
3. **AJ-E3004.** A write naming a pool the session isn't in echoed what the agent passed ("pool-default:proj-…") and not why. It names the pool by its name and, when a sealed pool holds the session, says so (P7 step 2). Unit test: `refusal_words`.
4. **AJ-E2104.** The session page's header said "Working" for a driven session between turns while its rail row said "Idle": the page now uses the rail's one vocabulary. Unit test: `session-model-state.test.ts`.
5. **Instant and paged.** The Pools tab was blank while it read; it shows a skeleton at once.
6. `lab_scenario.sh` gave the seeder the lab's HOME as the "real" one (an assignment on the same line); it takes the real home first.

Left, low:
- Review's Live lists messages that went, not one that was refused: the agent is told, the person isn't. To the 0.4 design list.
- The seeder made two launch settings named "Main" on the adopted Codex Account (the in-place import makes one), so Continue in another app offered "Codex · Personal · default" twice.
