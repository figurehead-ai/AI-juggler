## Earlier runs today, and what they found

1. **Run from inside a Claude Code session, Planner ran as that session's child**, with transcript saving off, so step 6's switch couldn't find its conversation ("AI Juggler couldn't tell which file holds this conversation"). Fixed in the product (`84211b97`); see the messaging lab's record. The labs now run in a clean environment.
2. **Stop didn't stop a busy Claude Code in AI Juggler's terminal**, so a switch's "Stop now" gave up: "The session didn't stop, so nothing was switched" (the switch took 15 s; the process was still there 30 s later; `ps` said it was exiting, state `E`). Two causes, both fixed in the supervisor with regression tests:
   - each terminal's output reader sent a "fresh output" hint on a bounded channel with a blocking send; with no one draining it, the reader stopped, the terminal's output backed up, and the tool could neither write nor exit (`50b0e1ef`; test `supervisor::reader_tests::a_full_activity_channel_never_stops_the_reader`, timed out before);
   - the terminal ladder's last step was portable-pty's kill, which is SIGHUP on Unix, a signal a process may handle; it now ends with SIGKILL, as the piped ladder does (`4aca0492`; test `supervisor::a_pty_session_that_ignores_term_and_hup_still_stops`, "still running 6.3 s after Stop" before).

   With both, the switch went through in the final run.
3. **Harness fixes:** the list view shows tasks only (D-44), so the epic and story are read from the plan; bridge calls are listed log by log, not in time order, so a step's call is matched by its arguments (step 5 had taken Builder's refused assign for Planner's; step 6's claim answer was another's); "no agent starts a session" means no new process (a tool's helper may end meanwhile); a target showing Claude Code's first-run setup is recorded BLOCKED, and no key is pressed there.
