# 0.5 gate triage (D-137): the a11y gate and the gallery specs, before the one baseline refresh

Date: 2026-11-20. Branch `release/0.5`, from 28dfcf7b7. Claude Opus (judgement and code).

## How it was run

- **The a11y gate** as CI runs it (`scripts/a11y_gate.sh`, natively; CI's
  `a11y-shard` job runs the same script on ubuntu-latest), with every
  gallery spec of `playwright.regression.config.ts`'s `GALLERY_SPECS`
  added to the same run (all their tests, not only the `@gate` states),
  `AJ_AXE_GALLERY=1 AJ_A11Y_EVIDENCE=1`, 6 workers, nice 10.
- **Run 1** (28dfcf7b7): 1898 tests, **92 failed**, 1800 passed, 6 skipped;
  axe summary 31 serious.
- **The pixel comparison** (`scripts/visual_gate.sh`, the pinned container)
  was **not run**: the image (by digest) and the node_modules volume are
  cached, but each `--rm` run asks corepack for pnpm, and offline
  (`--network none`) `corepack prepare pnpm@10` fails. That is a download,
  which this task may not make. Every `@gate` state differs from its stale
  baseline until the refresh anyway (class V below).

Each failure below names its message and its capture or context. Run 1's
log and JSON were kept in the session's scratchpad, not committed.

## Classes

- **D**: a real defect, fixed in the product.
- **T**: a broken or nondeterministic test: fixed at its cause (a pin, a
  stable signal, the load order, or a spec written before an approved
  change). No retries, no sleeps added.
- **V**: only an expected visual difference from 0.5's approved changes,
  covered by the refresh.

Counts (run 1's 92 failing tests, by cause): **D 8 causes (40 tests), T 21
causes (52 tests), V 0** in the local run. One more D (D9) was flaky: it
passed in run 1 and failed twice in six on a re-run.
