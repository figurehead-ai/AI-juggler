## What is new: a measured fidelity table per hop

`crates/juggler-app/src/features/switch_fidelity/` (reusable, unit-tested on the conformance kit's synthetic transcripts) measures one hop: what the source held at switch time against what the target actually received. Everything is read through the adapters' own readers: `parse_any` (the readers now also count tool calls, results, errors and images), each adapter's subagent reader, `used_in` and `inventory`, and the handover's own `state.json`. The lab (`tests/switch_lab_live.rs`, `tests/switch_lab/fidelity.rs`) calls it on every hop and writes `<out>.fidelity.md`.

The target received the history in one of three forms. Each is measured in the source's units:
- **Transplant** (the conversation itself): each source turn is found in the target's own transcript, by its id or its words.
- **Replay** (a handover file): each turn is whole (its words and every tool line quoted), shortened (only its opening words, as a left-out turn's topic) or missing. Tool calls arrive as one line each; results are summarised by those lines.
- **Switch back** (the original resumed, plus one "While you were away" update): only the work new on the away hops is measured (by id; a replay's opening, the handover itself, isn't work). Each new turn is whole, shortened (the update's one-liners) or missing.

Rows: user turns, assistant messages, tool calls, tool results (errors), images and attachments, the task list (each item with its state), subagents (and their folders), rules files in force, MCP servers the conversation used, the working folder, and the uncommitted changes (git diff stat).

Planted facts sit in the early, middle and late turns of the source, never in a file (checked). Some are said by the person (a codename, a ticket, a bucket). Some are said only in the model's reply (a port, a job name and a timeout it picked, read back as `PORT=`, `JOB=`, `TIMEOUT=`). One is a decision made only in the conversation (the rounding mode). Each target is asked every fact as `KEY=value` lines and each answer is scored answered, wrong or unknown. A Claude target is asked in a fork that isn't kept, so the probe never becomes part of what the next hop carries.

The verdict: **PASS** when nothing is lost and every fact is answered (a reduction the switch makes and says is not a loss), **FAIL** for a wrong fact or a moved folder or diff, **PARTIAL** otherwise.

The source conversation now has nine short turns on A (several tool calls, one subagent, the probe's MCP tool) and three on the Codex-started task.

### The environment of labs 15–18

Labs 15–18 (and the outside suite's first run) ran from a shell inside a Claude Code session, and inherited its variables. Among them: the parent session's markers, its routing (`ANTHROPIC_BASE_URL`), and a variable that turns on file checkpointing for headless runs. The lab cleared only `CLAUDE_CONFIG_DIR` and `CODEX_HOME`. So it is possible that those runs' requests followed the parent session's routing rather than the lab accounts' own sign-ins; nothing in the lab's records can tell. The file history labs 15–18 saw on A's headless turns came from the inherited checkpointing variable. An interactive Claude Code session keeps file history by itself, so the file-history fix stands.

The messaging lab found what the markers do to AI Juggler's own launches (transcript saving off). The launches now remove a parent session's markers (`84211b97`). Every lab now runs through `scripts/qa/lab_env.sh` (only the basics, the build's and the lab's own variables), and the harnesses refuse to start when `CLAUDECODE`, `CLAUDE_CODE_*`, `ANTHROPIC_*` or `OPENAI_*` is set. Lab 19 and the outside suite's lab 20 ran that way, and so did the final messaging and tasks labs.
