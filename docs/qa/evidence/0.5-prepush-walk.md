## Findings

### Blocker

**F-01 The downloadable model list never loads, so no model can be downloaded.** Settings > AI > Models shows "Can't read the list of tested models" under Other tested models; only Apple's built-in model is offered. `https://config.figurehead.ai/v1/{stable,beta,nightly,dev}.json` answers 404 (checked with curl, 2026-11-20 ~14:25 UTC); the compiled defaults (`models/builtin.json`) carry only Apple. So the Qwen3-1.7B end-to-end check (download, hash check, sandboxed helper, answer, Remove) could not start: there is no Download button. Repro: open Models in any Dev build. Fix is on the publish side (the signed `models` section must be published), not the app; until then 0.5's whole "Other tested models" and approval-card paths are unreachable for users. Capture: AJ-E3812/captures/models-1.jpg. The message says "it checks once a day", which is true but hides that nothing was ever published; consider a different line while the file does not exist.

### Should-fix

**F-02 "Turn reviews" is a switch with nothing behind it.** Models says "Writes a short review when an agent's turn ends" and Use it turns Turn reviews on (Beta), but `Job::Review` has no consumer: grep finds no command, view or code path that asks the router for a review (only the flag `ai_review_on`, the router table and tests). No review can be produced or shown, so the "one turn review" check could not run even with a model. Repro: grep `Job::Review` outside tests, router and models. Either wire the review or hide the job until it exists (D-127: never show what can't be used).

**F-03 Bot's suggested questions include one in German.** Empty panel, "Try one": "What needs me?", "What finished today?", "Was hängt gerade fest?" (`ui/src/lib/bot-ui-words.ts:53`). The rest of the app is English; the Mac's languages are English and Bosnian. If it's deliberate (showing Bot reads other languages), it reads as a mistake to a newcomer. Capture: AJ-E3804/captures/bot-1-panel-empty.jpg.

**F-04 "What changed today?" and Home disagree on the count.** Bot says "8 sessions finished", lists 6 rows and "and 7 more" (13); Home says "15 ended today". Three different numbers for one thing. Repro: lab K2, ask "What changed today?", compare with Home's "15 ended today" in the rail. (Possibly different windows, "today" vs "since midnight local"; the answer should name its window, and the count and the list must agree.)

### Later

**F-05 Settings shows a desktop App under a CLI name.** In Settings > Sessions the retention rows read "Retention for Claude Code CLI · Work Max" and "... · Side", but those are the two Claude (desktop) Apps. Wrong tool name in the label (found in the accessibility names while reading the page; not captured).

**F-06 Walk kit.** `lab_drive` stops when BetterStage's overlay (layer 26, bottom centre) covers the focused field: the Bot input sits in the covered strip when the window is placed at y=80. Not an app bug; a note for the walk kit: shrink the window (Dev's window would not resize through AX here) or place it at y=30 before typing.

- **N-03, N-05, N-07, N-08: later** (0.5.x): small clarity items, none blocking.

**CI's 13 failures, causes proven from the logs:**
- **The Apple helper's Swift** (rc-dev-app, four rehearse compiles, build-macos): `GenerationOptions(samplingMode:)` is macOS 27's SDK label; the runners build with macOS 26's (`sampling:`). Now chosen by `#if compiler(>=6.4)`, the same greedy sampling either way.
- **Windows checkout:** six evidence files named `…attention:facts_given.json`. Renamed to `attention-facts_…`. `scripts/portable_paths.py` (in verify-static) now refuses Windows-reserved characters, names and case clashes in tracked paths.
- **static (Rust):** the local engine's pressure switch was unused on Linux (my test fix). Now built on macOS only, where its one test is.
- **tests 5/6, router test:** it starts a helper, which only macOS does. Gated to macOS, as the engine's own such tests are.
- **tests 5/6, `trust.rs`:** no new network crate. `cargo metadata --offline` couldn't read the local-model helper's own lock, because CI fetched only the app's crates. The tests job now fetches the helper's lock too; the network list is unchanged.
- **build-macos, the sandboxed model load:** the runner is a virtual Mac (`kern.hv_vmm_present`). Its GPU isn't Apple silicon's `AGXAccelerator`, the one class the profile lets Metal open, and the same load passes unsandboxed on the same runner. The test skips on a virtual Mac and logs whether `AGXAccelerator` is present, which proves the cause in the next run. The profile is unchanged.
- **visual:** the PR body lacked notes for 104 of the refresh's 491 baselines. Added from the refresh review's notes.
- **CodeQL:** 27 alerts, all in test code: rollout-bucket names flagged as "salts", and fake keys or fixture paths printed in assert messages. False positives, to be dismissed with these reasons once the next run lists them.
- **Happo:** the diffs go to the coordinating session to check by eye.
