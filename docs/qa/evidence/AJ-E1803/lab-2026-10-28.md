## How it ran

- **The harness is committed now:** `crates/juggler-app/tests/agent_labs_live.rs` with `tests/agent_labs/`, run by `just agent-lab messaging <lab> <claude-profile> <codex-home> <out>`. On 10-26 an uncommitted harness stood in for the window; this one is the same idea, in-process:
  - an `AppState` over `<data>`, with the app's background work as `lib.rs` runs it without a window: the lifecycle forwarder, the 2 s tick (processes, the graph, the pools' cards) and the Needs you refresh, each part's panic caught and counted (none);
  - Builder is Codex, driven (its app-server), after AI Juggler's trust sheet is answered **Open restricted**;
  - Planner is Claude Code in AI Juggler's terminal; its prompts are typed into that terminal as a user types. Claude's own folder-trust question is answered yes, for `<lab>` only;
  - the bridge is the real `juggler-agent` behind a wrapper that logs its stdin and stdout lines, never its environment;
  - each step calls the same backend function as the window's command.
- **A clean environment.** The recipe now runs the lab through `scripts/qa/lab_env.sh`, which keeps only the basics, the build's variables and the lab's own. Both harnesses refuse to run when a Claude Code session's or a vendor's variables are present (`CLAUDECODE`, `CLAUDE_CODE_*`, `ANTHROPIC_*`, `OPENAI_*`). See finding 1.
- At most two real tools at once (one Codex app-server, one Claude Code), `DISABLE_AUTOUPDATER=1`, tiny prompts.
- **UI-only steps are BLOCKED**, as on 10-26: bubbles, buttons, the Needs you cards as drawn, and key presses. The backend data those views read was checked instead ("backend").

## Earlier runs today, and what they found

The harness ran seven times before the run above. What failed, and what was done:

1. **Run from inside a Claude Code session, every Claude session AI Juggler started took itself for that session's child.** Claude Code's screen said "Transcript saving is off — inherited CLAUDE_CODE_CHILD_SESSION marker". AI Juggler passed on the parent session's markers (its session and host ids, messaging socket and token, account ids). The same happens when AI Juggler Dev is started from a Claude Code terminal. **Fixed in the product** (`84211b97`, "a session AI Juggler starts is nobody's child"): launches, resumes and sign-ins remove a parent session's markers, as they already removed inherited credentials. Test: `vendor_default_folder::a_parent_sessions_markers_never_reach_a_launch`. The labs now run in a clean environment (`scripts/qa/lab_env.sh`) and refuse an unclean one. See the note on the earlier runs' environment in the switching lab's record.
2. **Harness, fixed:** the wrapper and its log folder must be in a folder only the user can write (the scratch folder under `/private/tmp` is not), so `<out>` is under `$HOME/lab`; the recipient's words were read from the thread's newest message, which was by then Builder's answer (now by the message's id); the hook note was expected to say "1 unread message" though earlier answers were unread too (now: a facts-only note naming You); the ack was counted after Planner had already acked on hearing the note.
3. **Claude's trust dialog under load.** Down, then Enter, 400 ms apart, was lost once while the dialog redrew (it puts the selection back on "No, exit"); Claude then exited. The harness now waits for the screen to settle and picks each key from the selection the newest frame shows.
4. **Clean-up timing.** A stopped Claude Code with transcript saving on took a few seconds to exit; the clean-up now waits, bounded at 30 s, and says how long it took.
