## Findings

1. **The lifecycle forwarder ends after its first quiet half-second** (`crates/juggler-app/src/lib.rs`, `spawn_lifecycle_forwarder`).
   - The loop is `while let Some(event) = state.supervisor.recv_timeout(500 ms)`. `recv_timeout` on a `std::sync::mpsc::Receiver` returns `None` on a timeout, so the thread ends the first time 500 ms pass without a supervisor event (in practice, right after start).
   - The harness copied the loop as it is and logged when it ended. It ended at once, in every run.
   - The effects seen:
     - after both sessions had exited (Claude by Stop, code 143; Codex code 0), their rows still said `running`, and so did the task view's `live`;
     - after a restart, sessions the user had stopped were stored as `failed`.
   - The Processes view's Left behind still worked (it comes from the ledger's reconciler; see the processes lab).
   - **Reproduction:** start AI Juggler Dev, start a session, Stop it, and read `select status from instances`. Or run a copy of the loop on a fresh `Supervisor` and log when it returns.
   - This was seen in the harness's faithful copy. Confirming it in the app needs a build of AI Juggler Dev (that build is the coordinator's).
2. **Codex's "Always allow" label still shows the shell wrapper.** The approval's summary is now the command (`printf '%s' lab > lab.txt`), so lab 2's bug 2 is fixed for the summary. But the Always option reads "Always allow `/bin/zsh -lc printf '%s' lab > lab.txt`", and its rule "commands starting with `/bin/zsh -lc …`" (`codex_appserver/asks.rs`, the execpolicy amendment's label).
   - **Reproduction:** driven Codex, Open restricted, "Write the word lab to lab.txt in this folder.", then `runtime_asks`.
3. **The hop-limit answer confuses the agent.** The `send_message` answer for the paused third note carries `hop: 3, hop_cap: 6` (the thread's agent-message cap) next to "the chain reached the hop limit" (the pool's limit, 2). Planner said: "That doesn't match the count: the same reply shows hop 3 of a cap of 6." The answer should name the pool's hop limit (2) when that is what paused it.
4. **One message, two Needs you cards.** While the chain was paused, Needs you held the `deliver` ask and also "Builder has a message waiting" for the same message. The second card's Deliver bypasses the ask's wording. Both are the user's click, so no hard line was crossed; it is a UX point.
5. **"1 min ago" for a message sent seconds before.** The duplicate refusal rounds up. "just now" would be right.
6. **One key counted twice.** `API_KEY=sk-lab-…` gave `secrets_found: 2`, withheld "1 secret values" and "1 API keys". The env-value and API-key detectors both matched the same span (`docs.rs` through `juggler_handover::redaction`). The pool's docs list would say 2 withheld for one key.
   - **Reproduction:** `share_doc` with that one line, then `messages_docs`.
7. **The pool's cards say "Unavailable — read only while it runs in AI Juggler"** for both members while they ran in AI Juggler.
   - Planner had a `transcript_ref` and Builder had none: the driver attaches it only when Codex reports a path under the account's home.
   - The card tick (`pools::cards::tick`) only publishes after reading a transcript. In the tasks lab the 2 s tick died at the time (finding 8 there). Here it didn't, and the card still said Unavailable.
   - Needs a look by the card's owner. The "Task" field was right (it comes from storage).
8. **`runtime_lab_snapshot.sh procs` says "(0)" when `pgrep` fails.**
   - Under a UTF-8 locale, `pgrep -f` stopped with "illegal byte sequence" because some process's arguments weren't UTF-8. `|| true` turned that into an empty list.
   - The snapshots' `sort` also follows the locale, so a `take` under one locale and a `diff` under another reports thousands of false adds and removes.
   - Run it with `LC_ALL=C` (this lab did); the script should set it itself.
