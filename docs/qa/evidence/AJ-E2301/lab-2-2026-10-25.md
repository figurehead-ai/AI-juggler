## How it ran, and what it could not run

- **AI Juggler Dev was not run.** Free disk was 23 GB at the start and 21 GB later, below the 25 GB floor for cargo. So `release/0.2` couldn't be built. The `juggler-app` in the shared target has none of E23's code (no `runtime_handover` and no `codex_appserver` strings), so it is an older build. No desktop control was available either, and the read-only test bridge can't launch. **Every check that needs AI Juggler's window, its audit table or its settings switch is BLOCKED.**
- **The tools were driven by hand, speaking AI Juggler's own wire shapes.** The shapes came from `codex_appserver/codec.rs`, `claude_stream/codec.rs` and `claude_hooks.rs` at 2414a4bd:
  - A Python harness in `<scratch>` (not committed) was the app-server client (stdio, and WebSocket over the unix listener) and the stream-json client.
  - A small PTY driver ran the real TUIs.
- **Every tool ran in a clean environment.** Only `HOME`, `USER`, `LOGNAME`, `PATH`, `LANG`, `TMPDIR`, `SHELL`, `TERM`, plus `CODEX_HOME` or `CLAUDE_CONFIG_DIR`, were set.
- **The stand-in for `juggler-agent hook`.** The overlay `--settings` file had AI Juggler's shape: nine hooks, 5 s timeouts, `PreToolUse` matched on `AskUserQuestion`. Its hooks called a lab script instead of `juggler-agent hook`. The script logged the event name and time only (never the payload), printed nothing and exited 0. It slept 3 s on `PermissionRequest` to time the dialog. The overlay also had a status line that printed a fixed word.
- **At most two real tool processes at a time.** The largest was one app-server plus nothing else, or one TUI.
- **What was never done:**
  - no sign-in, and no macOS "Allow";
  - no read of a credential file, the Keychain or a process environment;
  - no copy of a profile.
- **The trust answers.**
  - Claude Code's folder-trust dialog was answered **yes for `<lab>` only**.
  - Codex's "Trust this folder?" was **not** answered yes. Its trust choice is saved to the user's `config.toml`. Quit was chosen instead (finding 1).

## Bugs found (not fixed: the adapter's owner fixes them)

1. **Two `--settings`: Claude Code keeps only the last, so AI Juggler's hooks are lost** (`crates/juggler-adapters/src/claude_hooks.rs`, `injection`; its test `a_settings_file_elsewhere_is_left_alone` writes this behaviour down).
   - The injection puts `--settings <overlay>` first and keeps a user's own `--settings <file outside overlays>` after it.
   - Claude Code (seen on 2.1.310) applies only the last `--settings`. So the overlay's hooks never run: no exact state reports, and nothing warns.
   - Reversing the order would drop the user's file instead.
   - **Reproduction:**
     1. Write `A.json` and `B.json`, each `{"hooks":{"SessionStart":[{"hooks":[{"type":"command","command":"echo <A|B>-SessionStart >> /tmp/two.log"}]}],"SessionEnd":[…same…]}}`.
     2. In any trusted folder, run `CLAUDE_CONFIG_DIR=<profile> claude -p /usage --no-session-persistence --settings A.json --settings B.json` (no model call).
     3. `/tmp/two.log` has only `B-SessionStart` and `B-SessionEnd`.
   - Expected (the module doc's "the user's own hooks still run" and AI Juggler's): both files' hooks.
2. **A Codex approval's summary is the shell wrapper, not the command** (`crates/juggler-adapters/src/codex_appserver/asks.rs`, `command_ask`).
   - Codex 0.163.0 sends `command: "/bin/zsh -lc ls"` and `commandActions: [{type: "listFiles", command: "ls", path: null}]`.
   - The summary takes `command`, so Needs you would say "Asks you: /bin/zsh -lc ls", not "ls" as the checklist expects.
   - The fixture (`tests/fixtures/codex-app-server/messages-0.163.0.jsonl`) has an unwrapped `npm test`, so the tests don't catch it.
   - **Reproduction:** `codex app-server --listen stdio://`, `initialize`, `thread/start {cwd, ephemeral: false, approvalPolicy: "untrusted", sandbox: "read-only"}`, then `turn/start` "Run `ls` in this folder.". The `requestApproval` params show both fields.
3. **A Claude Code "add directory" suggestion is labelled "Always allow this, for this session"** (`crates/juggler-adapters/src/claude_stream/codec.rs`, `rule_words`).
   - Live `permission_suggestions` include `{type: "addDirectories", directories: [<folder>], destination: "session"}`, with no `rules` and no `mode`.
   - `rule_words` then falls back to "this", so the option doesn't say which folder it opens. Claude Code's own dialog says "always allow access to <folder> from this project".
   - **Reproduction:** the stream-json launch above, then "Run `echo lab > lab2.txt` with Bash." in a trusted folder. The `can_use_tool` request carries the suggestion.

## Findings (no code bug, or needing a decision)

1. **Open in terminal for Codex in a folder Codex hasn't trusted lands on Codex's trust screen.**
   - Driven sessions (`thread/start`) never ask about trust.
   - `codex resume <id> -C <cwd> --no-daemon` shows "Trust this folder? … Your trust decision will be saved" ("Trust and continue" / "Quit"). Trusting writes the user's `config.toml`.
   - The TUI also shows Codex's own update prompt ("Update now (runs `npm install -g @openai/codex`)" / Skip / Skip until next version).
   - So the first hand-over in a new folder is two vendor screens away from the conversation. This needs a decision: tell the user what to expect, or pass an in-memory trust choice. AI Juggler must not decide trust by itself.
2. **Codex's approval choices depend on the request.** For `ls` under `untrusted`/`read-only` they were only `accept`, `acceptWithExecpolicyAmendment` and `cancel`. `only_available` already offers just those, so Needs you would show Allow once, Always allow `ls`, and Deny and stop.
3. **Two clients on one Codex thread work, and approvals reach both.** The first answer resolves the request for both, and the command runs once. A second viewer (a TUI with `--remote`, or a second AI Juggler window) would see the same approval and could answer it too.
4. **`thread/resume` without `excludeTurns: true` brings a `deprecationNotice`:** "Full-history hydration is deprecated for paginated threads; use `excludeTurns: true`, then page with `thread/turns/list` and `thread/items/list`." The codec counts it as unknown. A future Codex may stop sending the turns.
5. **`/hooks` doesn't list `--settings` hooks.** The checklist's "/hooks lists both" can't be met. The "running … hooks 0/2" line and the hook logs are the evidence.
6. **`SessionStart` from `--settings` didn't run on a first start whose folder was trusted after launch.** It ran on the next start. In that case AI Juggler gets no start report, and `UserPromptSubmit` covers Working.
7. **This account's terminal starts in auto mode; `-p` starts in `default`.** Approvals in its terminal sessions are rare: `ls` and `echo` never asked.
8. **A profile used only through the Claude app gets Claude Code's onboarding on its first terminal run.**
   - The screens are the theme picker, the security notes, then the trust dialog, whose default is "No, exit".
   - Choosing a theme **created `<claude-profile>/settings.json`** (22 bytes, one key, `theme`). The file was left as is, for the maintainer to decide.
   - AI Juggler's first terminal session on such a profile will show these screens too.
9. **The first interactive start updated Claude Code for the whole Mac.**
   - The TUI said "✔ Update installed · Restart to update": `~/.local/bin/claude` moved from 2.1.302 to 2.1.310, with a new `versions/2.1.310`.
   - It also wrote `<claude-profile>/.last-update-result.json` and `cache/changelog.md`.
   - It cloned the official plugin marketplace into `<claude-profile>/plugins/marketplaces/claude-plugins-official/` (577 files) with `plugins/known_marketplaces.json`.
   - These are the tool's own writes on a terminal start, not the lab's. A later lab should set `DISABLE_AUTOUPDATER=1` for its terminal runs.
10. **`pgrep -fl` can show other processes' environment strings.** A process that rewrote its own argv area showed environment text in the `pgrep -fl` listing. That was seen once, in an ad-hoc listing; nothing from it was kept. `runtime_lab_snapshot.sh` uses `pgrep -fl` with the lab's patterns and saves the matches. It should print `pid` and `comm` only (`pgrep -f …` then `ps -o pid=,comm=`), so that no environment text can reach the snapshot folder.
