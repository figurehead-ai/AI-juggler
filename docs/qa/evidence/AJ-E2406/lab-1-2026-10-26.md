## Bugs (not fixed: the owner of E24 fixes them)

1. **Left-behind and ended processes are listed twice** (`crates/juggler-app/src/features/processes/`, the attention and ended views; the cause wasn't traced).
   - Each process came back twice with the same `key` (`p:<pid>:<start>`): once in its real state, once as `idle`.
   - The verify sheet's `tree_pids` repeated each pid too.
   - **Reproduction:** step 2 (crash route), then `processes_page {view: "attention"}`.
2. **"This PID now belongs to a different program"** is said for a process that simply exited.
   - **Reproduction:** stop a left-behind server whose parent shell then exits, then Stop… the shell.
3. **D-41b refuses every Homebrew python** (`features/processes/stop.rs`, `check`: `outer_bundle(exe)` gives `APP`).
   - Homebrew's `python3` executes `…/Python.framework/Versions/3.x/Resources/Python.app/Contents/MacOS/Python`, so it counts as "part of an app".
   - The page offers Stop (`stop: observed`) and the sheet then refuses with "This is part of an app. Quit the app instead."
   - The same happens to any CLI whose real executable sits in a helper `.app` inside a framework.
   - **Reproduction:** step 7 with Homebrew python, with the session ended (crash route).
4. **A zombie is never shown** (step 8).
   - The child was `Z` in `ps` for minutes, with the lab's python as its parent, inside an AI Juggler session's tree, and the graph never had it.
   - Likely the collector (sysinfo on macOS) drops processes whose details it can't read, which zombies are.
5. **This Mac doesn't list another app's CLI session** (step 10).
   - Only the Claude desktop app's own processes appeared under "Claude app". The Claude Code session running under it (in Processes, as "In a session Claude runs") was missing.
   - **Reproduction:** start `claude` from any shell under the Claude app (or Terminal), then read `this_mac_impl(..).others/top/by_tool`.

## Findings (no bug in AI Juggler, or needing a ruling)

1. **Claude Code takes its background tasks with it when it ends** (version 2.1.310).
   - This holds for a Stop, which sends TERM to its process group, and for `/exit` ("Exit and stop tasks").
   - It stopped them even when a task ignores TERM, starts its own process group, or runs under `nohup`.
   - With AI Juggler's Claude sessions, then, a "Left behind" server comes only from a crash (or the user's "Move to background and exit", not tried).
   - The checklist's steps 2, 5 and 6 assume a leftover after Stop. They should start one in a way that outlives the session, or use the crash route this lab used.
2. **A server started with `nohup … &` from a foreground Bash command is invisible.**
   - It leaves the session's tree before the 2 s tick sees it, and is reparented to launchd.
   - Processes never shows it, under the session or as a leftover, and nothing counts it.
   - This is how many agents start servers. It is the real gap for E24's "what a session leaves running" with Claude Code.
3. **One server counts as two leftovers:** the shell the Bash tool ran, and the server under it.
4. **The verify sheet lists a stale pid** among `tree_pids` (already exited).
5. **Cleanup history uses the folder name** ("aj-processes"), not the session's name ("Lab crash").
6. **The automatic rules never tidy a Claude Code background task.** Each runs in its own process group, and the preview says "It left its session's group". If that is the intended safety rule (D-08), the checklist's expected "Would tidy python3 now" is wrong for Claude. Otherwise the rule needs another identity check. Ruling needed.
7. **Homebrew python is named `Python`** (its executable's name), not `python3 (http.server)`.
8. **Another app's new session has an empty title** until it has one of its own.
9. **Other apps' Codex sessions repeat one process tree.** The Codex app's (ChatGPT's) six threads were six sessions, each showing the same app-server's 20 processes (the same root pid), so per-session totals repeat the same memory and CPU.
10. **The status's `processes` count flapped** between about 100 and about 240 on alternate ticks, with nothing started or stopped.
11. **The checklist's zombie command trips Claude Code's safeguards** on Opus 5.5. A neutral file name and asking it to run the script unread worked.
