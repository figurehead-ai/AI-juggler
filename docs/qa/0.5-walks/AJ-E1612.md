### The click guard (in `lab_drive`)

No click or keystroke is sent unless, at that moment, both hold:

- the frontmost app (NSWorkspace) is Dev's pid;
- the topmost on-screen window at the point (CGWindowList, active Space) belongs to Dev's pid.

If either fails, nothing is sent: `lab_drive` prints `WAITING: …` (what is in the way) and waits `AIJ_DRIVE_WAIT` seconds (default 120). Still failing, it stops (exit 3), nothing sent. The maintainer may be using the Mac. Dev with no window on screen at all (accessibility still reads its page; dry run 2 waited 45 minutes so) is the same: `WAITING: Dev's window is off screen (minimised/hidden/other Space)`. (`scripts/qa/floor_drive.swift` has no such guard: it is not used here.)

**Bringing Dev forward** (the dry run of 2026-11-16 waited 15 minutes behind another app). Only with `AIJ_DRIVE_MAY_ACTIVATE=1` on the command's own line (or `--may-activate`), never set in a profile or shell rc; off by default, so other walks never take the front. The dry run and this sitting turn it on. Then, when the guard fails because another app is in front or Dev's window is off screen, the driver brings Dev forward by its pid (no click or key): it un-hides Dev if hidden, un-minimises its main window if minimised (`AXMinimized` false), makes that window main, raises it and makes Dev frontmost; when the main window is still on another Space (macOS switches no Space for an app with any window on this one: dry run 3's small 280x168 Dev window kept it there for hours), it moves it here by minimising and restoring it (a window restored from the Dock opens on the Space in use). "Dev's window" is always its **main** window (titled "AI Juggler" or "AI Juggler · …"), never another of Dev's windows; never by name (the installed AI Juggler is also `juggler-app`), never ⌘⇧M, never another app's window. And only:

- when nobody has touched the Mac for **20 s** (HID idle time);
- while the screen isn't locked, no screen saver runs, and this login is the one on screen;
- **once per step** (one `lab_drive` command), never in a loop. Then the guard is checked again: Dev still not frontmost, or its main window still off screen, stops the step at once (exit 3, `STOPPED <UTC> step=<command>: … after bringing it forward (ACTIVATED, MOVED (refused)) …`, nothing sent), never a wait that can't end. Record it and bring the window here by hand (Mission Control, or Dev's Dock icon) before running the step again.

Each part prints its own line for the record, in that order: `UNHID` / `UNMINIMISED` / `ACTIVATED` / `MOVED <UTC time> step=<command> idle=<s>s` (only the parts it needed; `(the system refused)` after one that didn't take). After it, any new input at the Mac stops that command at once (exit 6, `STOPPED: someone used the Mac …`): nothing more is sent, and Dev is left where it is. The full guard still runs before every single event, and keys and presses only ever go to Dev's pid. A stopped step is run again once the person is done; record it as stopped, not failed.

**Pressing by name.** A button is pressed by its exact accessible name, never a prefix, and that name must belong to **one** control in Dev's window: two controls with one title stop it (exit 4), whatever `--in` says. A row's control is pressed with `--row "<the row's own name>"`: the row (its named group) must be the only one with that name, and the button must sit inside it. Home's Needs-you rows are named per App: the row `<App> needs its sign-in` holds the button `Sign in to <App>` (`<App>` is its full name, e.g. `OpenCode CLI · lab A`); the words on screen stay "lab A needs its sign-in" and "Sign in".

## The dry run (sonnet, before the maintainer is invited)

The whole sheet on stand-in tools (`scripts/qa/standins/`): each answers what its adapter runs, writes its sign-in where the real tool would, answers "lab", resumes, and gives usage in the adapter's shapes; none touches the real home or the network (fake pages on `example.invalid`). The dry run proves the driver, the labels, the order and the guards; it proves nothing about the real tools (each stand-in's head says what it can't).

**Idle time.** The dry run needs about **30 minutes with the Mac idle** (nobody at the keyboard or mouse, Dev's window not minimised or hidden): the guard sends nothing while someone uses the Mac, and Dev is brought forward only after 20 s without input. Dry run 2 lost 45 minutes to a Mac in use. So the driver says so when it starts, before `setup`, in its first message to the coordinating session (for the maintainer): "The AJ-E1612 dry run starts now and needs the Mac idle for about 30 minutes; anything you do meanwhile pauses it."

**Opportunistic.** The dry run runs every driver command with `--opportunistic` (or `AIJ_DRIVE_OPPORTUNISTIC=1` on its line, beside `AIJ_DRIVE_MAY_ACTIVATE=1`): the maintainer's own input pauses the step instead of stopping it (`PAUSED <UTC> step=<command> idle=<s>s`, nothing sent, Dev left where it is), it resumes after 20 s without input on an unlocked screen with no screen saver (`RESUMED …`, then the full guard, at most one bring-forward per resume, and the interrupted press or key restarted whole), and waits have no time limit (`HEARTBEAT …` at most every 10 min), so it can run overnight; other agents' apps in front are only the guard's to wait out. The idle time it reads is the person's: the HID state also counts the driver's own posted keys (dry run 3: `PAUSED … idle=0.0s` after every typed key, about 8 minutes per `send`), so the driver keeps each key's moment in the run's input ledger (`drive-log/lab_drive-<run>.input.json`) and leaves those out; a pointer event, or a key between two of its own, is still the person's and pauses it. A `send` of the sheet's words should now take seconds with no PAUSED line.
