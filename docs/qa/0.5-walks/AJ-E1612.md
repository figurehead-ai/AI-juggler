# AJ-E1612 live check: OpenCode, Kimi Code, Grok Build, ZCode, Muse Code (scenario T16)

The run sheet for the 0.5 sign-in sitting (D-107). Each tool gets two fresh lab Apps in AI Juggler Dev: **lab A**, which the maintainer signs in, and **lab B**, left signed out. Agents drive every step; the maintainer only finishes each tool's browser step (their page: [AJ-E1612-maintainer.md](AJ-E1612-maintainer.md)). The setup is `docs/qa/scenarios/T16-new-tools-live.toml`.

## Who does what

- **Driver: sonnet.** Follows this sheet by AI Juggler Dev's pid only, one or two tools at a time. Every click and keystroke goes through the click guard (below).
- **Checker: Opus.** Checks each FAIL, and each PASS that closes a requirement, against this sheet and its capture before anything is recorded.
- **The maintainer.** Finishes the browser or device-code step for lab A of each tool, and any macOS prompt. Nothing else.

## Fixed facts

- **The lab:** `/tmp/aij-lab-t16`, a throwaway HOME (0700). AI Juggler Dev runs on it, so every tool it starts sees the lab as its home. Ten Apps (`OpenCode CLI · lab A`, `OpenCode CLI · lab B`, … `Muse Code CLI · lab B`), each made the way Add a fresh app makes it, with its own folder under the lab's AI Juggler Dev data. One project: `<lab>/repos/lab`.
- **The build:** the lab's Dev app, `scripts/build_dev_app.sh lab`: a debug Dev build with `lab-bridge`. Only it carries the lab's Muse switch (`AIJ_LAB_MUSE_SIGN_INS=1`, set by `lab_scenario.sh`), which gives each Muse App its own sign-in file through `TBH_CREDENTIAL_BACKEND=file`. A release build can't contain it.
- **No other AI Juggler Dev may run.** Dev runs once per Mac, so a second one hands over and quits; `lab_scenario.sh open` says so if it happens. The installed AI Juggler is a different app: never touch it, and drive Dev by its pid only (both are `juggler-app`).
- **Never read a secret.** Sign-in files are looked at by name and date only (`scripts/qa/lab_sign_ins.py`). The Keychain is read with `security find-generic-password` **without** `-w`, and only the item's date is kept.
- **Never open a tool's own app window.** ZCode's sign-in and sessions run its engine with `ELECTRON_RUN_AS_NODE=1`, with no window.
- **Harmless prompts only:** "reply with the word lab"; nothing else is typed into a session.
- **Quota exhaustion is recorded only if it happens.** Never force it.

### The click guard

No click or keystroke is sent unless, at that moment, both hold:

- the frontmost app (NSWorkspace) is Dev's pid;
- the topmost on-screen window at the point (CGWindowList, active Space) belongs to Dev's pid.

If either fails, nothing is sent: the driver stops and reports. Buttons are pressed by exact title, never by a prefix. The maintainer may be using the Mac.

## Per tool (one or two at a time)

**Sign in** is the same action for every tool. On Home, under **Needs you**, find the row "lab A needs its sign-in" whose line names the tool ("OpenCode's own sign-in, in a terminal here…"), then press its **Sign in**. The rail's Needs you lists the same rows. Never press a lab B row. AI Juggler opens its own terminal and runs the tool's sign-in in lab A's folder. The driver answers the tool's menu in that terminal (guarded keys). The maintainer finishes the browser step.

| Tool | What the Sign in runs | Driver picks in the terminal | Maintainer finishes in the browser |
|---|---|---|---|
| OpenCode | `opencode auth login` (XDG data, config and state in lab A) | Provider **OpenAI**, then the ChatGPT sign-in (not an API key) | ChatGPT sign-in with their existing ChatGPT subscription |
| Kimi Code | `kimi login` (`KIMI_CODE_HOME` = lab A) | nothing: it prints a device code and its page | enters or approves the device code on Kimi's page |
| Grok Build | `grok login` (`GROK_HOME` = lab A; Claude and Cursor sharing off) | nothing | xAI sign-in on the page it opens |
| ZCode | ZCode's engine `login` (`ZCODE_DATA_BASE_DIR` = lab A), no window | nothing, or Z.AI if it asks | Z.AI sign-in on the page it opens |
| Muse Code | `muse login` with `TBH_CREDENTIAL_BACKEND=file`, `HOME` and every `XDG_*` in lab A, `MUSE_NO_AUTO_UPDATE=1`, no `MUSE_AUTH_PATH` | nothing | approves Meta's sign-in code on the page it opens |

The exact program, words and environment of every Sign in are in `<lab>/sign-ins.json`, written by the seed and checked by `lab_sign_ins.py check`.

### The checklist, for each tool `<t>` (opencode, kimi-code, grok-build, zcode, muse-code)

Record every step with `--record docs/qa/evidence/AJ-E1612/<t>.md` (anonymized). Pid-window captures go through `swift scripts/qa/redact_capture.swift` into the same folder, and each is opened by eye and confirmed with `scripts/qa/check_captures.py --confirm`.

1. **The sign-in stays separate.**
   - Dev shows lab A **Signed in** and lab B **Not signed in**.
   - `python3 -I scripts/qa/lab_sign_ins.py check --home /tmp/aij-lab-t16 --signed-in <every tool signed in so far>`: lab A has its sign-in file in its own folder, lab B has none, and nothing else changed.
   - `python3 -I scripts/qa/lab_sign_ins.py real --compare --home /tmp/aij-lab-t16`: every real sign-in file unchanged.
   - Muse only: `python3 -I scripts/qa/lab_sign_ins.py muse-gate --compare --home /tmp/aij-lab-t16`. If the Keychain item's date CHANGED, stop the Muse part and tell the maintainer to run `muse login` once in their own terminal.
2. **A session starts.** New session → `<Tool> CLI · lab A` → project `lab`. Send "reply with the word lab"; it answers. ZCode has no terminal: its session is driven in AI Juggler's own conversation view, which proves its first live turn and the provider-headers reply.
3. **It resumes.** End the session from AI Juggler, then Resume it from its row. The same conversation comes back (its earlier turn shows). Send "reply with the word lab" once more.
4. **Usage is read.** Open lab A's usage (its App page and Usage). Record what it shows and the source line it names. Tool notes:
   - Kimi Code: its windows come from `kimi web` (labelled experimental).
   - Grok Build: whether its token reading comes from `signals.json`.
   - ZCode: limit hits from its store, and the reset's time zone.
   - Muse: the 5-hour and weekly windows.
   - If the screen says it can't read usage, record the reason it gives.
5. **Quota exhaustion.** Only if it happens during the sitting: capture the screen and the tool's own message. Never run anything to cause it.
6. **lab B stays out.** Lab B still reads Not signed in. Starting a session on it shows the tool's own "sign in first" or AI Juggler's reason, not lab A's account.

After each tool: stop its sessions from AI Juggler, then list that tool's processes by pid, start time and folder only. Stop any started in the lab that's still running, and name it in the record.

## After

1. Stop every lab session from AI Juggler.
2. Record the final `real --compare` and, for Muse, `muse-gate --compare` (the saved state lives in the lab, so this comes before the teardown).
3. Quit Dev by its pid (`kill <pid>`), then `scripts/qa/lab_scenario.sh teardown T16`. It stops everything with a file open in the lab and removes it.
4. Check that nothing of the lab runs: `pgrep -fl aij-lab` prints nothing, and no `opencode`, `kimi`, `grok`, `muse-bin` or ZCode engine process started during the sitting is left.
5. Open every capture by eye before it's kept.
