## Rules (read first; a broken rule stops the walk and is reported, never worked around)

1. **Only AI Juggler Dev and lab profiles.** Never the maintainer's real profiles, the installed AI Juggler (it has the same process name, `juggler-app`: address Dev by its pid, never by name), or the Mac's real Claude, Codex or ChatGPT apps.
2. **Read-only on real accounts.** Nothing is written under the real `ClaudeProfiles`, `Claude`, `.claude`, `.codex` or `ClaudeCodeProfiles` folders. Credential files and Keychain items are never opened.
3. **No sign-ins, no system Allow presses by the walker.** Lab profiles show Claude's sign-in window: never type or click in it. A system dialog is photographed and logged (Z1), never answered; the maintainer (or the harness's own permission flow) answers it. Where a step needs a grant, it says "ask the maintainer".
4. **Every keystroke guarded.** All input goes through `scripts/qa/lab_drive.swift` (build once with the system `swiftc` into the scratch folder; run `lab_drive guard` first), which checks that Dev is frontmost and topmost at the point before every key, click and wheel click. Never type with another tool. A `PAUSED`/`STOPPED` line means the maintainer is at the Mac: wait.
5. **Tool-folder snapshot before and after** (paths, sizes, mtimes only, never contents): `scripts/qa/runtime_lab_snapshot.sh take before <tool folders>` at step A3, `take after` at Z2, then `diff before after`. Any change under a real (non-lab) folder is a blocker.
6. **D-37: never read another process's environment** (no `ps eww`, `ps -E`, `launchctl getenv`, `/proc`-style reads). Processes are listed by pid and program name only (`runtime_lab_snapshot.sh procs`).
7. **Decline every download.** Bot's local-model offer is looked at and declined; nothing is fetched (no curl, npx, pip, brew). Screens that offer a download are captured, not accepted.
8. **Reap every launched app.** Every Claude profile, Dev window or helper this walk starts is listed in the Launched table (end of sheet) when started and shown gone by `lab_apps.py list` and `runtime_lab_snapshot.sh procs` at Z3. No blank window is left.
9. **Fill every Result cell before any teardown.** `lab_scenario.sh teardown PL1` is run only at Z4, after Z1–Z3 are recorded and Opus has checked the verdicts. A teardown before that deletes the sign-ins and the evidence's context.
10. Every launch goes through `scripts/qa/lab_env.sh <command>` (clean environment, no Claude Code session markers).
11. Record against the step's number. Result is `PASS`, `FAIL (finding)` or `BLOCKED (why)`. A step that fails is still followed by the rest, then the whole walk is repeated once the finding is fixed (`docs/qa/persona-validation.md`: one findings list, triaged once). Feedback over 100 ms and anything over 1 s with no progress cue is noted in the Record cell.
12. Captures: opened by eye before they are kept; real names redacted only by `scripts/qa/redact_capture.swift` through `lab_drive shot`; name them `S<step>-<what>-<light|dark>.jpg`.
