# 0.3.9: the switch that never worked, traced and tested at its real size

On 2026-11-04 the maintainer switched a long Claude app conversation from the Default profile's account to another Claude account on 0.3.8. The window said "switching" for several seconds with nothing moving, then "The switch didn't complete. Something went wrong on the way to the other account, so nothing moved. Try again." Retry failed the same way. Earlier releases had each failed this journey in a different way. This page records what was wrong, why the tests missed it, and how 0.3.9 was tested.

## What the installed 0.3.8 recorded (read-only)

- The switch graph has both tries, each stopped at the copy step: no file reached the target, and the source was untouched.
- The conversation's transcript was **798,500,574 bytes**. Its folder (subagents and tool results) held 502 MB in 1,719 files, and its file history 20 MB in 904 files.
- A bundle read each file whole into memory, refused past 512 MB (`SESSION_FILE_MAX`, a guard against a damaged or hostile file). The refusal reached the switch as an I/O error, and every adapter error became the same generic words, with Retry, although a retry could never pass.

Behind it, two more faults the first would have hidden:

- **The after-launch check.** It required the source to be byte-identical after the new session started. A conversation open in the Claude app keeps writing at its end (the app's own bookkeeping lines, a reply finishing), so even a small open conversation could fail here, after the new session was already running.
- **Codex.** The same whole-file read applied to rollouts. This Mac has a 7.6 GB rollout and a 496 MB compressed one.

## Why the tests missed it

Every handover fixture was a few kilobytes, and every check ran against a source nobody wrote to. The live lab of 2026-10-22 switched short, headless conversations. Nothing exercised the size or the open-in-the-app state of the conversations people actually switch.

## What changed

- Large files travel as frozen on-disk copies (APFS clones: no time, no space) in the bundle's own scratch folder, removed with the bundle; a bundle keeps at most 32 MB in memory in all.
- Every check streams: hashes, the torn-tail check (a window that grows for a very long last line), the compaction marker, a collision's fork. Codex rollouts too; a compressed one is decompressed as a stream onto disk, bounded at 64 GB.
- The after-launch check is a prefix check: the source must still start with exactly what was carried.
- The window shows each step as the backend reaches it, with a bar and the seconds so far.
- Failures say what happened; Retry shows exactly when the words say trying again can work (a test holds the two together for every failure); Copy details copies the words, the program's detail and the time.

## How it was tested

Synthetic data of the real shape, never the maintainer's conversation: an 800 MB transcript (4 KB turns, a 2 MB tool output every 5,000 turns, a compaction), 1,719 folder files, 904 file-history files.

| Run | What it covers | Result |
|---|---|---|
| `switch_real_size` (juggler-adapters, release build) | the real Claude adapter through the real switch pipeline; the source appended to after launch | switched in 5.0 s; byte-identical; all files there; steps reported in order; peak memory 68 MB (460 MB before the in-memory budget) |
| `switch_real_size` (juggler-app, release build) | AI Juggler's own switch command, accounts and profiles, launch through a stand-in `claude`, the source written to every 150 ms during the switch | switched; what landed is a whole-line prefix of the source, at least as long as when the switch began; all 1,719 folder files there; 7.2 s on a quiet Mac |
| the same, target folder not writable | the words, detail and Retry that reach the window | "AI Juggler wasn't allowed to write to acme-max's folder, so nothing moved. Check its folder's permissions, then try again."; Retry shown; Copy details has the stage and the system's reason, the home folder written `~` |
| `switch_real_size` at 7.8 GB (juggler-adapters, release build) | the size of the largest Codex rollout on this Mac | switched in 30 s (the Mac under load); peak memory 75 MB; cloned, so no disk space used; no scratch left |
| `a_switch_to_a_nearly_full_disk_stops_before_filling_it` | a target account on a mounted 64 MB disk image | stops before writing: "There isn't enough free disk space … AI Juggler always leaves 4 GB free. It needs about 3.9 GB more."; nothing left on the image; the source untouched |
| `disk_room` | the room check, and a disk filling up mid-copy (free space read through the test seam) | refused up front with how much more it needs; a copy stops within a few checks of the reserve |
| unit tests | a 40 MB transcript with a 3 MB last line and 300 history files; a collision fork of it; a source written to after bundling; a large Codex rollout, plain and compressed; a grown source passes the after-launch check and a rewritten one doesn't | pass |
| interface tests | the step marks follow the backend's events and never go back; a permanent failure has no Retry; Copy details carries the detail | pass |

Run them with:

```sh
cargo test -p juggler-adapters --release --test switch_real_size -- --ignored --nocapture
cargo test -p juggler-app --release --test switch_real_size -- --ignored --nocapture
```

## Time, and what it depends on

The app-level 800 MB switch took 7.2 s on a quiet Mac and 14 to 28 s while other work loaded it (load average 15 to 43). With and without the source being written to, the times followed the load, not the writes. A sample showed the time in the system's own calls (`open`, `fclonefileat`, `read`), with no other app work running. Most of a switch is reading what it copied three times to check it: what was carried, what landed, and the original afterwards. Those checks are what make it safe, so they stay.

## Disk space

On a Mac the copy is an APFS clone: no time and no space. It writes in full only where a clone can't be made (another disk), for a fork (the target already has the conversation), or for a packed Codex rollout (unpacked as it's copied). Each of those checks for room first and again every 64 MB, and stops while 4 GB is still free. The switch screen shows the size, what the copy takes and what's free before it's confirmed; when there isn't enough, Switch waits, with Check again.

## Still open

- A switch to another Mac carries a conversation only up to 512 MB (the bundle is sent in one message).
- The full bug report flow and a debug mode (a detailed local log of switches and launches) are planned for 0.4.
