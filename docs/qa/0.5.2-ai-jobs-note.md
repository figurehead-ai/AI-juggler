# The four AI jobs still off, on Apple's on-device model: why, and how to get each to pass (AJ-E3827)

For the maintainer's decision. Written by the 0.5.2 builder (Opus), 2026-11-25, from the final model tests (`docs/qa/evidence/AJ-E3709/v5-final.md`, harness v5, round 3), their verdicts (`v5-round3-ef/verdicts-opus.md`) and the shipped gating (`crates/juggler-app/src/features/ai/jobs.rs`). Nothing is changed until you rule on it.

**Two facts change the picture.**
- One of the four isn't held back by the model at all. **Turn review already passed on Apple's model** (81 % value, 0 criticals after the fixes; D-131 allowed it as an opt-in Beta). It's off only because the feature that writes and shows a review, AJ-E3820, was never built.
- v5 already used per-job prompts with worked examples, guided output (Apple's `DynamicGenerationSchema`, constrained decoding), datamarked inputs and a facts guard. So "add structured output and few-shot" isn't the gap. The misses below have specific causes, and each has a specific fix.

## Each job

| Job | Apple today vs the bar | Why it misses | What would close it | Effort | Recommendation |
|---|---|---|---|---|---|
| **Turn review** | Passed: 81 % preferred over the plain excerpt; 0 criticals after fixes | Not the model: nothing writes or shows a review yet (AJ-E3820) | Build AJ-E3820: the review written at each turn's end, shown on the session page and in the feed, behind its Beta switch | M (UI + job wiring; the model path and checks exist) | **Build it in 0.5.2 and turn it on as an opt-in Beta on Apple.** It's the quickest real AI win. |
| **Watches from Bot** | 70 % exact (19/27, English/German) vs a 95 % bar | 42 of the 80 English/German misses were our own code (owner names with spaces, a session word inside a name, unnamed targets beside named ones), 6 were the scorer, 27 the model. Apple's own failure: it fills the open `unsupported_asked` text field with a restatement (58/60 drafts) and lists several targets (41/60); greedy retries repeat the same draft. | (1) Make `unsupported_asked` a short enum, not free text, and allow exactly one target in the schema. (2) Two small calls instead of one: pick the target from the user's own sessions (a constrained choice), then the condition. (3) Retry with a little sampling, not greedy. (4) The code fixes already landed (db623bc74, 8b3a2f909, 83d3861af); re-measure with them. | M: schema and prompt change, one harness round (60 fresh requests) | **Fix and re-measure. If it reaches ≥ 90 % exact, ship it as "Bot fills the Watches form": you see the draft and click Add, so a wrong field is caught before it counts.** Every AI draft needs your click anyway (D-131). The 95 % bar was set for a watch made without one. |
| **Feed line** | Safe (0 criticals) but preferred only 43 % of the time over our plain excerpt; the bar is "preferred" | Not unsafe, just not better: our code excerpt already reads well, and the model's lines are longer and blander | Change the task: the model picks the one most telling fact from the turn and the verb, and code renders the line (a constrained choice between the turn's own facts), plus 2–3 examples of a good choice. Measure preference again on fresh turns. | M: one harness round | **Re-try once with the "pick, don't write" design; ship only if it's preferred over the excerpt.** Otherwise keep the excerpt: it's the better product today. |
| **Digest** | Safe (0 criticals) but preferred only 33 % over the code roll-up (Apple's lowest) | Asked to compose a whole digest in one go, the small model loses the thread. Five composition problems are listed in v5-round3-ef. | Map and reduce: the model writes one short line per session (the feed-line task above), and code assembles the digest, ordering, grouping and counting. The model never writes the whole digest. | M–L: reuses the feed-line work plus code assembly | **Do it after the feed line.** If the per-session lines win, the digest follows almost for free. Until then the code roll-up stays. |

None of these clears the watch bar as run (70–89 %). The schema fix above applies to all of them.

## What I recommend you decide

1. **Turn review:** build AJ-E3820 in 0.5.2 and offer it as an opt-in Beta on Apple's model (a D-number).
2. **Watches:** apply the schema and two-step fix, then re-measure. Ship as "Bot fills the Watches form" at ≥ 90 % exact, with the user's click as the final check. This lowers D-131's 95 % bar for drafts you confirm.
3. **Feed line, then digest:** one harness round each with "pick, don't write" and map-and-reduce. Ship only if preferred.

Each harness round uses fresh blind sets, judged once, as v5 did (model-evals-need-a-real-harness). The run is on this Mac, one model at a time. No real transcripts are needed (D-124).
