# 0.5 — the order of work

The 28 tasks the roadmap's [0.5 section](ROADMAP.md) names, in the order
they are built on `release/0.5`. Started 2026-11-12 under D-104: 0.5 may
start before the first Stable, and **a 0.4.x finding always preempts it**.

What counts as done is what `scripts/release_scope.py` checks: the task's
header says `Status: DONE…` **and** `docs/qa/evidence/<id>/manifest.md`
has a row naming `R<N>` with `PASS` (or `DEFERRED (D-NN)`) for every
numbered requirement N. Rows labelled `Req.N` don't count, so every
manifest touched here is relabelled `R1`, `R2`… as it closes.

```bash
python3 -I scripts/release_scope.py report 0.5
```

2026-11-12: 28 named, 0 done and proven, 28 open.

## How the batches are ordered

1. **Nothing waits on the maintainer first.** A batch whose proof needs a
   sign-in, a spare account, a ruling or a service the maintainer creates
   goes last. Inside a batch, a requirement that needs one is marked
   ⏸ and listed in [What waits on the maintainer](#what-waits-on-the-maintainer).
2. **Nearly done before new.** The IN-PROGRESS tasks whose remaining proof
   is ours close first.
3. **New tools only behind the adapter seams** (ADR-0019: a tool is data
   plus its adapter; no tool id outside its adapter; the conformance kit,
   AJ-E1521, passes for each).
4. **UI batches follow the specs.** Each reads the wireframes, the
   deep/11 UX spec and SPEC §9 first, gets a design critique before its
   baselines, and is walked by hand in the real app (works, speed,
   clarity, layout).

Every batch: small commits that each build, `verify-static` before each
commit, lazy loading for new screens and heavy readers, captures from
fixtures only. Walks and evidence drafts run on Sonnet, scans on Haiku;
code and every PASS/FAIL that gets recorded are checked on Opus.

## Release

No release pull request until batch 1 is proven. Pushes go to
`release/0.5` only (never to `main`), at milestones, after the local
gates. A tool added in 0.5 that hasn't been proven live when 0.5 reaches
Stable is marked as a preview inside it (the roadmap's rule).
