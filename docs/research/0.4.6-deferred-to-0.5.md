# 0.4.6 exit RC (rc3h): non-blockers deferred to 0.5

Written by the 0.4.6 release session, 2026-11-19. These came from the rc3f–rc3h walks and the fix agents' "left open" notes. None is a blocker under the triage rule for 0.4.6's exit RC (data loss, wrong account or action, a crash, security or privacy, a core flow broken). After 0.4.6 reaches beta, the 0.4 line takes blockers only (D-114), so all of them go to 0.5. rel-05: please give each an E-id (or fold it into an existing task) and queue it.

## Pools and messages
1. **The Pools grid still moves when a pool is made.** A new pool took slot 3 and pushed the project pool down, then moved again. 7695e15e0 holds the order only after the first move on the screen. Wanted: a stable order for the whole visit, with a new pool at the end.
2. **Naming a project pool by its project ("web") is refused when the session is only in a custom pool on that project.** Example: "isn't in a pool called "web"; the only pool it belongs to is web team". Decide whether a session is in its project's own pool too, or make the refusal say how to reach it.
3. **The hop counter's words.** The pause chip reads "3 agent messages in a row without you, over this pool's limit of 2", where the person expects "N of 2". Also: a delivering pool doesn't pause at its hop limit when the recipient is a desktop member or a terminal session AI Juggler can't type into; it only stops waking it.
4. **Pool setup's side panel** says "Open a session in web: it joins" while the every-new-session switch is off. The Who's in step repeats the connector paragraph twice. P1's sheet also expects the side panel to say who joins now and who joins later; today only the review step does.
5. `shortPoolName` (Settings › Agent access) doesn't shorten a told-apart name such as "web · all sessions (in lab)".
6. Deleting a pool is only at the foot of its settings panel. The List view's right panel doesn't scroll by wheel.
7. In a Work together pool, approving a held message takes two presses: Allow once (into the inbox), then Deliver (wake now). This is by design (D-119), but X1 scored clarity 3. It's a UX question for the maintainer.

## Sessions, New session, switching
8. **During a terminal hand-over the sidebar shows two rows for the session.** Home's last-12-hours list shows both "h-b Finished" and "h-b Stopped by you".
9. **New session suggests the maintainer's other projects first, and Recent reshuffles.** Its layout shifts when the memory line appears.
10. **The Stop toast names the folder** ("Stopping web · …"), not the session.
11. **The switch dialog** (Continue in another app…) at 1280×800 didn't show its "what comes along" part or a Cancel, and didn't scroll there. Check its layout at the minimum window.
12. The pool wizard's steps can't be pressed from its left rail.
13. **Recovery limits** (from F-rc3f-3's agent): a driven session whose conversation file was deleted still ends in a failed `-t`. A session with no turn yet, quit under a build from before d4c840a46, fails once more after the upgrade. A cross-Mac switch back takes the original's name, not one given on the other Mac. A rare race: if a live look is already running when a process ends, it can write the entry back until the next look.
14. Codex: whether a message the person adds during a running Codex turn comes back as a `userMessage` item isn't verified live. If it doesn't, those messages won't show as "You".
15. **Usage readings:** the Claude codec's `percent()` reads any value ≤ 1 as a fraction, so a whole "1" would read as 100%. A week on one model from the stream shows only on the session panel, still labelled "Weekly".
