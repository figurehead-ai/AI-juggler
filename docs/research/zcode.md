# Research notes: ZCode (Z.AI / GLM)

> Deep dive compiled 2026-10-12 as input to the [proposal](../PROPOSAL.md) and [spec](../SPEC.md).
> Combines web research with local inspection of a real installation (macOS, desktop 3.14.5 / CLI engine 0.16.9).
> Legend: **[V-W]** = verified web · **[V-L]** = verified locally (exact command) · **[I]** = inference · **[U]** = unknown.
> ZCode is newer and less documented than Claude Code / Codex — unknowns are expected and are flagged precisely.

## A. Web research

### A1. What ZCode is (Oct 2026)

- **[V-W]** ZCode is Z.ai/Zhipu's "next-gen vibe-coding tool" — a multi-agent desktop coding app, branded "GLM-5.3 official Harness." Electron app (`.dmg`/`.exe`/`.AppImage`/`.deb`/`.rpm`) for macOS (arm64/x64), Windows, Linux (beta). Site version v3.15.1. (https://zcode.z.ai/, https://zcode.z.ai/cn/docs/install)
- **[V-W]** ZCode is one of "20+ Agent Tools" covered by the **GLM Coding Plan** subscription (alongside Claude Code, Codex, Cline, Kilo Code, OpenCode, Clawdbot/OpenClaw). One subscription = one shared quota pool across all those tools. (https://z.ai/subscribe, https://docs.z.ai/devpack/overview)
- **[V-W]** Plan tiers (credits system, revised 2026-07-30): **Lite** 2,000 credits / 5h, 10,000/week; **Pro** 12,000/5h, 60,000/week; **Max** 28,000/5h, 140,000/week. Credits = `(input×in-mult + cached×cached-mult + output×out-mult) / 10,000`; GLM-5.3 multipliers 6.9/1.7/24, GLM-5.3-Flash 2.3/0.56/8. 5h credits reset 5h after consumption (rolling, like Claude); weekly resets every 7 days from purchase. (https://docs.z.ai/devpack/overview, https://docs.z.ai/devpack/notice/usage-revision)
- **[V-W]** Pricing: official docs say "from $18/month"; third-party tracker lists Lite $18 / Pro $80 / Max $168 monthly (https://codingplan.org/Coding%20Plans). Treat as soft — promos are frequent.
- **[V-W]** Off-peak billing: 50% credit rate; peak = weekdays 14:00–18:00 UTC+8, weekends all off-peak. Z.ai has run all-day off-peak promos (e.g. Sep 25–Oct 7 2026). (https://docs.z.ai/devpack/overview, https://sessionwatcher.com)
- **[V-W]** GLM Coding Plan endpoints: Anthropic-compatible `https://api.z.ai/api/anthropic` (coding plan) and OpenAI-compatible `https://api.z.ai/api/paas/v4` (standard API); CN mirror BigModel `https://open.bigmodel.cn/api/anthropic`. **[V-L]** Confirmed in `/Applications/ZCode.app/Contents/Resources/config/provider/zcode-builtin.json` (templates: `zai-api`, `zai-standard-api`, `bigmodel-api`, `bigmodel-standard-api`).
- **[V-W]** ZCode-specific features beyond a plain CLI agent: Goal mode (long-horizon planning), subagents, plugins/skills/MCP/hooks/slash commands, automations (scheduled tasks), **idle-time tasks** (queued jobs that run free during compute-idle windows without consuming plan quota — requires a personal Coding Plan), remote development, Bot Channel (invoke ZCode remotely via WeChat/Feishu/Telegram), Memory, repo Wiki, browser automation. (https://zcode.z.ai/cn/docs/ sidebar)

### A3. Terms of service — multi-account, automation, wrappers

- **[V-W]** ZCode User Agreement (https://zcode.z.ai/cn/terms, Chinese; translated):
  - **3.2:** evidence of "improper registration or improper use of multiple accounts" → ZCode may freeze/close accounts and refuse service. No definition of "improper"; no explicit per-person account cap — it targets *improper* multi-accounting. **[I]** Running 2 paid personal accounts in parallel is a grey zone, not expressly banned, but risk-controlled.
  - **3.3:** the account is for personal use only; no third-party authorization/transfers.
  - **Section 4** prohibits using the service "via deep links, page scraping, social bots, spiders or other automated means" to access unlicensed data/servers/accounts; reverse engineering ZCode's "algorithms, source code, mechanisms"; circumventing safety measures; training competing models. **[I]** This clause is web-scraping-oriented; ordinary CLI/headless use of your own account is the product's own designed usage (`-p`, app-server) — a third-party wrapper that drives ZCode is not addressed head-on.
  - Third-party API keys: ZCode is then "only a local execution channel."
- **[V-W]** GLM Coding Plan Usage Policy (https://docs.z.ai/devpack/usage-policy): "**Subscription benefits are exclusive to the subscriber: Account sharing or multi-user access is prohibited**"; the plan "may only be used within officially supported tools and products"; violations → "rate limiting, account freezing, or other restrictions"; >3 violations may ban; appeal via Plan Overview page.
- **[V-W]** FAQ: all supported tools share one subscription's quota; quota visible on the subscription management page; subscriptions non-refundable. (https://docs.z.ai/devpack/faq)
- **[U]** No English z.ai Terms of Use page with a clean "one account per person" clause was found; the authoritative documents are the ZCode 用户协议 and DevPack usage policy above.

## B. Local inspection (macOS, 2026-10-12)

### B1. CLI location, version, surface

- **[V-L]** `which zcode` → not found; no shim in PATH. The CLI engine is a Node SEA-style bundle inside the app: `/Applications/ZCode.app/Contents/Resources/glm/zcode.cjs` (14.8 MB), run via `node …/zcode.cjs …`. Desktop 3.14.5 (`dev.zcode.app`, URL scheme `zcode://`); CLI reports 0.16.9; `zcode doctor` works (node v26.10.0, darwin/arm64).
- **[V-L]** `zcode --help` — commands: `app-server`, `commands`, `doctor`, `login` (Z.AI OAuth; `--no-browser` prints URL), `logout`, `plugins`, `skills`, `tui`, `version`. Notable flags: `-p/--prompt`, `--resume <sessionId>`, `-c/--continue`, `--json`, `--mode build|edit|plan|yolo`, `--surface terminal|desktop`, `--cwd`, `--attach`, `--disallowed-tools`, `--target`, `--browser-use headless`, `--locale`, `--no-browser`, `--verbose`. Subcommand `--help` just reprints top-level help (no per-subcommand docs).
- **[V-L]** Bundled extras: `Resources/tools/{ripgrep,bfs,ugrep}`, `Resources/cua-helper/ZCode Computer Use.app`, `Resources/config/provider/zcode-builtin.json` (provider templates), `Resources/glm/packages/*`.

### B2. `~/.zcode/` map

- **[V-L]** `~/.zcode/cli/` (54 MB) — CLI state: `config.json` (JSON), `db/db.sqlite` (5.4 MB + WAL), per-session data in `exec/sess_*`, `agents/`, `artifacts/sess_*`, `log/zcode-YYYY-MM-DD.jsonl` (~4 MB/day), `plugins/{cache,data,marketplaces}`, `rollout/model-io-sess_*.jsonl`, `shell-snapshots/`.
- **[V-L]** `~/.zcode/v2/` (3.6 MB) — desktop state: `credentials.json` (**0600**), `setting.json` (48 top-level keys incl. `receivePreviewUpdates`, `autoDownloadAndInstallUpdates`, `modelIoFullRetentionEnabled`, `memoryEnabled`), `provider_config.json`, `tasks-index.sqlite` (tasks, task_groups, automations, **off_peak_tasks**), `certs/`, `logs/`, `crash/`.
- **[V-L]** Config format is **JSON** throughout. `~/.zcode/cli/config.json` schema supports `mcp.servers`, `hooks`, `plugins`, and `storage.dir`/`storage.sessionDbPath` overrides. Project-level config: `<repo>/.zcode/config.json` or `<repo>/zcode.json`; user instructions `~/.zcode/AGENTS.md`.

### B3. Sessions & transcripts

- **[V-L]** Canonical session store is **SQLite**: `~/.zcode/cli/db/db.sqlite`. Tables: `session, session_entry, session_input, session_target, message, part, permission, todo, input_history, local_setting, model_usage, turn_usage, tool_usage, workflow_*, dwf_*, schema_migration`. `session` columns include `id (sess_UUID), project_id, parent_id, directory, path, title, version, summary_*, time_created/updated/compacting/archived, task_type, trace_id` — `parent_id` + `/fork` imply forking is first-class.
- **[V-L]** Raw model I/O mirroring: `~/.zcode/cli/rollout/model-io-<sessionId>.jsonl` — one JSON object per model request incl. request headers (⚠ headers may include auth → treat files as sensitive). Gated by `modelIoFullRetentionEnabled`.
- **[V-L]** Resume: CLI `--resume sess_…` / `-c`; TUI `/resume`, `/fork`, `/rewind` (checkpoint restore). `exec/sess_*/` dirs hold per-session shell snapshots + tool-call logs.

### B4. Auth

- **[V-L]** Credentials are a **plaintext JSON file** (mode 0600): `~/.zcode/v2/credentials.json` — **not** macOS Keychain (`security find-generic-password -s zcode` → not found). Keys (values redacted): `oauth:zai:access_token`, `zcodejwttoken`, `oauth:zai:user_info`, `oauth:active_provider`, and per-account entries `account-provider:coding-plan:account:zai-individual-coding-plan:account:<UUID>:api-key` — **the schema already anticipates multiple stored accounts plus an "active provider" pointer.** **[I]** Account switching = rewrite `oauth:active_provider` (and the oauth tokens) in this file.
- **[V-L]** `zcode login` = Z.AI OAuth; CLI and desktop **share** these credentials.
- **[V-L]** Env vars in the bundle (names only): `ZCODE_DATA_BASE_DIR`, `ZCODE_PERSONAL_PROVIDER_CONFIG_FILE`, `ZCODE_SESSION_ID`, `ZCODE_SKILL_DIR`, `ZCODE_PLUGIN_ROOT`/`ZCODE_PLUGIN_DATA`, `ZCODE_PRODUCTION_BASE_URL`, `ZCODE_REMOTE_HTTP_PROXY`, `ZCODE_TELEMETRY_*`, `ZCODE_RG_BINARY`/`UGREP_BINARY`/`GIT_BINARY`, plus `XDG_DATA_HOME`/`XDG_CACHE_HOME` reads.
- **[V-L, controlled experiment]** `ZCODE_DATA_BASE_DIR=/tmp/x zcode plugins list` still read `~/.zcode/...` — the var does **not** redirect plugin/config/db roots in 0.16.9. But `HOME=/tmp/y zcode plugins list` fully redirected state (created `/tmp/y/.zcode/...`). **Full-home isolation via `HOME` works; `ZCODE_DATA_BASE_DIR` alone is insufficient.**

### B5. Usage & quota

- **[V-L]** Local usage is comprehensive: `model_usage` logs per-request `provider_id, model_id, input_tokens, output_tokens, reasoning_tokens, cache_creation_input_tokens, cache_read_input_tokens, computed_total_tokens, duration_ms, time_to_first_token_ms, finish_reason, retry_count, error_type`; `turn_usage`/`tool_usage` aggregate per turn/tool. **[I]** Because plan credits are a deterministic formula of these token counts and the published multipliers, a manager app can compute exact credit burn per session/account locally — no API needed.
- **[V-L / U]** Remote quota (5h/weekly pools) is fetched by the app from zcode.z.ai/api/v1 + z.ai endpoints. **No official public quota API or CLI status command exists.**

### B6. Update mechanism

- **[V-L]** Electron with electron-updater (Squirrel.Mac): `Squirrel.framework` present; `Resources/app-update.yml` ships a placeholder (`provider: generic, url: http://localhost:8081`); runtime `setFeedURL(...)` overrides it. User toggles: `receivePreviewUpdates`, `autoDownloadAndInstallUpdates`, `skippedElectronUpdateVersions`. **[I]** CLI engine updates only with the app bundle.

### B7. Multi-account isolation assessment

- **[V-L]** Best mechanism: run the CLI with a **per-account `HOME`** (e.g. `HOME=<juggler-state>/zcode-acctA`), which provably isolates credentials, session DB, plugins, logs, and settings. The desktop app additionally keys off Electron's userData dir but shares `~/.zcode`, so parallel ZCode accounts are CLI-only (or one desktop instance per macOS user).
- **[V-L / I]** `ZCODE_DATA_BASE_DIR` is insufficient (B4 experiment); `storage.dir` in config.json gives partial isolation (sessions) without moving credentials.
- **[I]** Parallelism within one account: `app-server` (stdio, one per process) and `-p` headless runs are process-per-session; caps are server-side credits. A manager can run N sessions of one account and meter credits via `model_usage`.
- **ToS overlay (A3):** a supervisor that spawns ZCode processes with isolated HOMEs stays in "local execution channel" territory. Z.ai explicitly bans improper multi-account use, account sharing, and unsupported-tool use of the *plan*; a shipping product should rely on documented surfaces (CLI flags, app-server protocol, SQLite reads) rather than patched binaries.

## Key unknowns (honest list)

1. No public ZCode harness docs for CLI flags/env vars — all CLI knowledge here is from local `--help` and binary strings; Z.ai documents only the desktop app.
2. No documented public quota/usage HTTP API; reverse-engineering the app's own endpoints would be ToS-sensitive — out of scope for AI Juggler.
3. Production auto-update feed URL unknown (runtime `setFeedURL`).
4. Whether ZCode will ever ship as a standalone npm/brew CLI; today it is app-bundle-only.
5. Community pain-point evidence is indirect (docs revisions, third-party tracker positioning) — no quotable forum threads retrieved.

## C. Re-checked 2026-11-13 (before building AJ-E1605)

- **[V-L]** Desktop 3.15.3 (`CFBundleShortVersionString`), engine still 0.16.9 (`node …/zcode.cjs version`, run in a throwaway `HOME`; it wrote nothing there). Commands and flags as B1, plus `--workflow-mode`, `--target-replace`, `--force-mcs`, `--memory-bench`, `--mode guarded`.
- **[V-L]** The app ships no Node.js of its own (`Contents/MacOS/ZCode` is Electron; no `node` in the bundle); `zcode doctor` reports the Node it runs on (`node-bundle` artifact).
- **[V-L]** The engine reads `ZCODE_STORAGE_DIR` (default `~/.zcode`; the beta build sets `~/.zcode-beta`) for `cli/` and its other state, and `ZCODE_DATA_BASE_DIR` (default the home folder) for `<base>/.zcode/v2/credentials.json` and its telemetry state: strings in `zcode.cjs`. Together they give an account its own tree without moving `HOME`. Not documented by Z.ai; the adapter checks them at launch.
- **[V-L]** `cli/db/db.sqlite` (schema read with `immutable=1`): tables `session` (`id`, `parent_id`, `directory`, `title`, `version`, `time_created`, `time_updated`, `time_archived`, `task_type`, …), `message`, `part`, `model_usage` (`session_id`, `provider_id`, `model_id`, `status`, `started_at`, `input_tokens`, `output_tokens`, `reasoning_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`, …), `turn_usage`, `tool_usage`, `todo`, workflow tables. With ZCode closed there is no `-wal` beside it, and a plain read-only open fails ("unable to open database file"): a reader must open it `immutable` then, as the OpenCode store does.

- **[V-L, the engine's own code, 0.16.9; read while building AJ-E1605]** `ZCODE_STORAGE_DIR` does not move the session store. The store is the engine's `storage.sessionDbPath`, whose default `~/.zcode/cli/db/db.sqlite` is resolved from the home folder whatever `storage.dir` says; the engine's environment layer (variables starting `ZCODE_`, above the user and project config) moves it with `ZCODE_SESSION_DB_PATH` (or `ZCODE_SESSION_DB`). An account's tree therefore needs three variables, not two: `ZCODE_STORAGE_DIR=<account>/.zcode`, `ZCODE_DATA_BASE_DIR=<account>` and `ZCODE_SESSION_DB_PATH=<account>/.zcode/cli/db/db.sqlite`. The credentials path is `<ZCODE_DATA_BASE_DIR or home>/.zcode/v2/credentials.json`, as above.
- **[V-L, same]** The user config is read from `~/.zcode/cli/config.json` (home-based; no variable moves it short of `HOME`), so every account shares its MCP servers, hooks and plugin settings. On the live checklist (AJ-E1612).
- **[V-L]** `zcode --help` (0.16.9): `-p/--prompt` defaults to `--mode yolo`; the TUI has no option for a first message or a model. `doctor` in a throwaway `HOME` with the variables set wrote nothing anywhere.

## D. Undocumented-route pass, 2026-11-13 (AJ-E1605 round 2, D-106)

Read in the installed engine's own code (`ZCode.app/Contents/Resources/glm/zcode.cjs`, engine 0.16.9, desktop 3.15.3); nothing was run but `version`, and no `~/.zcode` was opened. Each finding names the code it rests on (the bundle's minified names, which change between builds; the strings don't).

- **[V-L] No route moves the user settings per App.** The user config is `yLe(path)`: the given path, else `join(K0("~/.zcode/cli"), "config.json")`, `K0` expanding `~/` with `os.homedir()` (`HOME`). `userConfigPath` is passed only by the `hooks` subcommand's own option and internal callers; `parseGlobalArgs` (`strict: true`) has no config option; the environment layer `parseEnvConfig` maps only `STORAGE_DIR`, `SESSION_DB_PATH`/`SESSION_DB`, `HTTP_PROXY`, `NO_PROXY`, `AGENT_CA_CERT`, `HTTP_TIMEOUT`/`TIMEOUT`, `LOG_FORMAT` and `MAX_TOOL_CONCURRENCY`. Not built: only a moved `HOME` would do it, ruled out in round 1.
- **[V-L] Rules and skills follow the home folder too (corrects round 1's module docs, which put skills under `storage.dir`).** User rules: `join(HOME || USERPROFILE || os.homedir(), ".zcode", "AGENTS.md")`; skills: `resolveDefaultSkillRoots`, `homeDirectory ?? os.homedir()` + `.zcode/skills` and `.agents/skills`, then the project's. Plugins follow `storage.dir` (per App). So every App shares one set of servers, hooks, rules and skills; AI Juggler lists and sets up that set in `~/.zcode` for every App, and says so (`zcode_inventory`).
- **[V-L] MCP servers' shape.** `mcp.servers.<name>`: stdio `{command, args, cwd, env}`, http/sse `{url, headers, oauth}`, plus `protocolVersion`, `enabled`, `timeoutMs`; `normalizeMcpServerConfigInput` reads `environment` as `env`, `enable` as `enabled`, `remote` as `http`, `http_headers` as `headers`, and infers a missing `type`. A user server's values are taken as written (only a plugin's `${ZCODE_*}` are expanded); a stdio server's environment is the engine's own (proxy and telemetry variables filtered) with its `env` over it. So a secret is left out of `env` and comes from the user's environment; a header's can't, so such a server isn't set up. **Contradicts § A2:** no `~/.agents/mcp.json` fallback exists in 0.16.9 (the only `mcp.json` the engine reads is a plugin's `.mcp.json`).
- **[V-L] No first message and no model option for the terminal.** `parseGlobalArgs`' options are `help`, `json`, `output-format`, `no-color`, `no-browser`, `browser-use`, `browser-executable`, `prompt`/`-p`, `memory-bench`, `attach`, `cwd`, `locale`, `resume`, `target`, `target-replace`, `continue`/`-c`, `force`/`-f`, `force-mcs`, `mode`, `verbose`, `version`/`-v`, `prepare-storage`, `stdio`, `surface`, `workflow-mode`, `all`/`-a`, `available`, `keep-data`, `scope`/`-s`, `sparse`; the first positional is the command (`tui` when none), any other word "Unknown command". `--target` runs headless like `-p` (a `/goal` prompt). The TUI's startup options (`runTui`) carry `initialMode` and `initialModel`, no prompt; its hooks live in the shared user config, so no per-launch state report could type one either. The model is the provider registry's selection, read from the App's own `<ZCODE_DATA_BASE_DIR>/.zcode/v2/provider_config.json` (`ZCODE_PERSONAL_PROVIDER_CONFIG_FILE` would swap the whole provider file, keys included: still removed from every launch). So each App keeps its own model already, and a pack can't start a ZCode session.
- **[V-L] No local record of the plan's pools.** The billing routes (`/api/v1/zcode-plan/billing/current` and `/balance`) appear once each, in the endpoint table, and nothing in the engine calls them (the desktop app does). Its tables (`session`, `message`, `part`, `model_usage`, `turn_usage`, `tool_usage`, `local_setting`, workflow and task tables) hold no quota; a call refused at a limit leaves `model_usage.error_type` (HTTP 429 is `rate_limited`), with no level or reset. The model-call records (`cli/rollout/model-io-<session>.jsonl`) can hold request headers with the sign-in, and are never read. The 5-hour and weekly pools stay the caps the user enters; burn is Computed.
- **[V-L] Titles and turns.** `session.title` is `not null` and the TUI runs with title generation on (read since round 1). A message's `data` is a JSON object with its `role`; a part's has its `type`, a text part its `text` (and `synthetic` for the engine's own notes). AI Juggler reads a session's user and assistant text for a pack, and refuses a record in any other shape whole (`zcode_sessions::turns`). The `session` table's creation statement has no `task_type` (a later migration adds it, as read on the real store in § C).

## E. Round 3: no terminal UI, so a driven runtime (2026-11-13, AJ-E1605 round 3, D-106)

Checked live in a throwaway home (no sign-in, no prompt, nothing written to `~/.zcode` or the app bundle), and read in the installed code: the engine `ZCode.app/Contents/Resources/glm/zcode.cjs` (0.16.9) and the desktop app's `Contents/Resources/app.asar` (3.15.3). **Live checks.**

Only the standalone build (not distributed) has the terminal UI. Rounds 1–2's terminal launch is withdrawn.
- **[V-L] The app's own runtime runs the engine.** `ELECTRON_RUN_AS_NODE=1 ZCode.app/Contents/MacOS/ZCode <engine> version` prints `0.16.9` (Node.js 24.14.0 inside), so no Node.js of the user's is needed.
- **[V-L] `session/create` with `importedHistory` works with no sign-in and no model call.** Run through the adapter's own code (`zcode_app_server::live_import`, below): the engine's app-server, started as the adapter starts it, took a two-turn conversation, wrote the session (the given title, the work folder), the user turn marked `metadata.migrationSource = "claudeCode"`, the assistant turn at cost 0 and zero tokens, two text parts, no `model_usage` row; then it ended by itself when its stdin closed. The adapter's own store reader read the two turns back exactly.

**Protocol facts used (the engine's own schemas, 0.16.9).**

- **[V-L] Wire.** NDJSON, one message per line, `{id, method, params}` / `{id, result}` / `{id, error:{code, message}}` / `{method, params}`, no `jsonrpc` field, no `initialize` (`ZCodeProtocolNdjsonConnection`; the union `PXt` of strict objects). The same shape as Codex's app-server, so the codec reuses Codex's line classifier.
- **[V-L] How the desktop starts it.** `resolveElectronRuntimeZCodeAgentCommand`: `{command: process.execPath, args: [<engine>, "app-server", "--stdio"], env: {ELECTRON_RUN_AS_NODE: "1"}}`, with `ZCODE_BUILTIN_PROVIDER_CONFIG_FILE` and `ZCODE_PERSONAL_PROVIDER_CONFIG_FILE` from `createNodeProviderRuntimePathEnv` (`resolveSpawnEnv`). The built-in file in the app is `Contents/Resources/config/provider/zcode-builtin.json` (`resolveZCodeBuiltin…`: `process.resourcesPath` + `config/provider/zcode-builtin.json`).
- **[V-L] Provider settings at start** (`prepareCliProviderRuntimeEnv`, for `tui`/`app-server`/`agent-server`/`login`/`logout`/`-p`): with both variables set it uses them as given; with only the built-in one, it copies it to `<data base>/.zcode/v2/runtime/provider/<platform>/<version>/endpoint-<hash>/zcode-builtin.json`, `<version>` being the build constant `__ZCODE_VERSION__` (undefined in this build: `0.0.0-dev`; no variable sets it), and the personal file defaults to `<data base>/.zcode/v2/provider_config.json` — the App's own. `ZCODE_APP_VERSION` only feeds the engine's telemetry (`productVersion`), so AI Juggler leaves it unset rather than pass for the desktop app.
- **[V-L] Methods** (`ii`): `session/create` (`qXt`: `sessionId` only with `importedHistory`, `workspace {workspacePath, workspaceKey}`, `persistence` `immediate|deferred`, `titleGenerationEnabled`, `mcpServers`, `model`, `mode`, …), `session/resume` (`WXt`: `sessionId`, `workspace?`, `mcpServers?`), `session/subscribe` (`$Xt`: `sessionId`, `deliveryKind` `desktop-continuous|web-remote-replayable`), `session/send` (`QXt`: `sessionId`, `content`, …; refused while a prompt runs), `session/stop` (`rQt`). The create/resume answer is a snapshot whose `session.sessionId` names it.
- **[V-L] Events** come as `session/event` notifications `{eventId, sessionId, turnId?, seq, timestamp, type, payload}` (`Pci` → `notify`). Read: `turn.started`, `turn.completed` (`resultType` `success|cancelled|error_*`), `turn.failed` (`error {type, message, code?}`), `part.delta` (`field` `text|reasoning|input|output`, `delta`), `tool.updated` (`kind` `started|result|error|…`, `toolCallId`, `toolName?`), `permission.resolved`, `userInput.resolved`. A sub-agent's events carry its own session id and are left out.
- **[V-L] Requests to the client.** `interaction/requestPermission` (`{requestId, sessionId, toolCallId, toolName, riskLevel, reason, input, options:[{optionId, kind, name, description?, response:{decision, reason?}}]}`; the answer is validated as `_F` `{decision: allow|deny|escalate|modify, reason?, …}` — i.e. the chosen option's own `response`); `interaction/requestUserInput` (`{prompt, questions:[{header, question, multiSelect, options:[{label, description?, value}]}], …}`, answered `{action: accept|decline|cancel, content?}`, AskUserQuestion's answers as `content.answers{<question>: <label(s)>}`, `Iuc`/`Sii`); `interaction/requestProviderRuntimeHeaders` before every model call (`mai`), answered `yQt` `{headersApplied: true, requestAuth: {apiKey?, apiKeyId?, accountScope?, headers?}}` or `{headersApplied: false, errorMessage?}` (then the call fails "Provider runtime headers were not applied before model request attempt."). Server request ids are strings `server-N`; an unanswered request may be sent again with a new id (`reannounceIntervalMs`), any of its ids answering it.
- **[UNCONFIRMED] Sign-in for turns.** AI Juggler answers the headers request with `requestAuth: {}` (never a credential, ADR-0003). Whether the engine then uses the App's own stored sign-in (`resolveModel(requestAuth)`) is not known without a signed-in lab profile: AJ-E1612 (D-107) sends one tiny prompt there; a sign-in failure is shown as "ZCode couldn't use this App's sign-in".

**Limit hits (keyless, measured by counts only).** A real store's `model_usage` holds 236 refused calls (`status = 'error'`, `error_type = 'rate_limited'`, `error_code` empty); every one has Z.ai's message in exactly the shape `[1308][Usage limit reached for 5 hour. Your limit will reset at YYYY-MM-DD HH:MM:SS][<30 hex>]` (138) or `[1310][Weekly/Monthly Limit Exhausted. Your limit will reset at YYYY-MM-DD HH:MM:SS][<30 hex>]` (98), 116 characters — established with `GLOB`/`instr`/character-class counts, no text read. The engine's own table (`["1308", …]`, `["1310", …]`: `ModelRateLimited`, not retryable; the quota set `hHs`) knows only the codes. **[UNCONFIRMED] Time zone**: read as UTC+8 every 5-hour reset falls 0.002–4.5 h after its hit (as UTC: 8–12.5 h, impossible for a 5-hour window), so resets are read as UTC+8. **[UNCONFIRMED] 1310's window**: its resets fell 5.6–6.5 days after the hit (a week fits; the words say "Weekly/Monthly"), read as the week.

**Gaps, each with its route checked (D-106).**

- **Per-App skills, commands and MCP.** A per-App plugin is possible in principle (the App's own plugin store `<storage.dir>/cli/plugins`, follows `ZCODE_STORAGE_DIR`; manifest `.zcode-plugin/plugin.json` with skills, commands and `mcpServers`), but its enablement is the key `plugins.enabledPlugins["<name>@<marketplace>"]` in the shared `~/.zcode/cli/config.json`, and installing it means running the engine's `plugins marketplace add` / `plugins install` under each App. That writes the user's shared settings for every App and needs an install step the inventory seam doesn't have, so it is left for a later round. `mcpServers` on `session/create` would carry a per-session set, but AI Juggler keeps no MCP set of a ZCode App's own (one set in the home folder serves every App), so nothing is passed.
- **Later messages into a running session** (the mailbox, `ZCODE_MESSAGE_ENABLED`/`ZCODE_MAILBOX_ROOT`): lower priority; a driven session takes the next message as a turn.
- **The plan's pools**: only z.ai's quota endpoint with the Coding Plan authorization (a credential) — out (ADR-0003).
