# System prompts: the registry (PAT-OSP)

Every system prompt AI Juggler can cause, one entry each (AJ-E1547; the design system's §5.10, PAT-OSP). AI Juggler never raises a system prompt the user wasn't told about first.

- **The gate** is `juggler_platform::os_prompt` (`crates/juggler-platform/src/os_prompt/`): the system's words for each kind of prompt, the calls that ask, and `Gate::through` (our sheet first for an entry not primed, then the call, then the outcome said; background work never prompts). The app's half is `crates/juggler-app/src/os_prompts/`: this registry in code (`registry.rs`), the ledger of primed entries, the window's sheet (`ui/src/components/OsPromptSheet.tsx`) and the IPC setup uses (`os_prompts_list`, `os_prompt_prime`, `os_prompt_status`, `os_prompt_request`).
- **The lint** `scripts/os_prompt_lint.py` (in `just platform`, so in verify-static) keeps every prompt-raising API inside the gate.
- **This table and the code agree**: `os_prompts::tests::the_design_doc_lists_every_entry_and_its_triggers` fails when an id or a trigger is missing here.
- **The walks** log each system dialog they see in `docs/qa/evidence/os-prompts/<version>.md` by these ids; an UNPRIMED line fails the release (`scripts/release_scope.py`, from 0.5.1).
- **Never** a privacy reset: no `tccutil`, no write to the system's privacy database. The registry is built by code audit and Apple's documentation.
- **Windows** (UAC's elevation, SmartScreen's "Windows protected your PC") and **Linux** (portals, polkit) get their entries when those ports start (PAT-OSP-6, D-52). macOS words are macOS 14 and 15's; a newer version may word a dialog a little differently, which the walks' log catches.

How the gate keeps the usability answers (PAT-USE, AJ-E1547 (6)):

- No sheet with no dialog after it: an entry the system already decided (allowed, or not allowed) gets no sheet; the call is made (it can't ask) and the outcome said.
- Not now is never a decline for good: it primes nothing, and the next click asks again.
- Not now is said, never silent (0.5.1 F28): the sheet stays with its outcome, "Nothing was asked.", the entry's "If declined" and where (or when) it's offered again (the registry's `offered_again`: a Settings place, or the next use that asks), with Done.
- The sheet's words are the registry's (AJ-E1555): its heading is the entry's title in every phase, the line under it never repeats it, and its body is the entry's why and what to click, then after the call what came of it in the entry's own words (`after`: what works now; `if_declined` with where to change it): never a state word such as "Asked." or "Allowed". A prompt that didn't appear is never reported as asked; for Bot's helper, the sheet says whether the helper started.
- The same sheet never shows twice: an entry is primed once (setup's card or the sheet's Continue); several calls waiting on one entry share one sheet.
- No dialog without a sheet first: every asking call is in the gate (the lint), and background work waits.

## Checked and not a prompt today

- **Full Disk Access**: nothing reads a TCC-guarded path outside the folders above (no `~/Library/Mail`, Messages or Safari).
- **Apple's on-device model** (`juggler-apple-ai`): `FoundationModels` asks nothing; its network check (`NWPathMonitor`) asks nothing. Its first start is the `helper` entry.
- **The local model helper** (`juggler-local-ai`): runs under `sandbox-exec` and `taskpolicy`, asks nothing; its first start is the `helper` entry.
- **`juggler-agent`** (the agent bridge): started by the tools, not by AI Juggler.
- **Microphone, camera, location, contacts, calendars, photos, Bluetooth**: no code uses them.
- **A tool's sign-in page** (AJ-E1545 R8, AJ-E1553: `crates/juggler-app/src/features/sign_ins/mod.rs:open_page`, the opener's `open_url` for an `https` page its adapter read): opening a web page in the default browser asks nothing. AI Juggler makes no other call for a sign-in: the tool's own sign-in runs in AI Juggler's terminal, and the "signed in?" check reads file metadata and Keychain item names only (the `keychain` entry's quiet path).
- **A move, its Undo, a repair, Finish and startup recovery** (0.5.1 F93, `crates/juggler-app/src/features/handover/moving_prompts.rs`): the one prompt a move can cause is `automation-app-links` (its link after the move, and Undo's back where it was). The offer and each move record list it while it isn't primed, and the Move button or Undo shows its sheet over the switch dialog before anything quits; the move itself never asks. Not now still moves: no link, the App started, the done screen says to pick it in the sidebar or click Open. Quitting is a signal to the exact process and starting refuses a `first-open` app, so neither asks; no guarded folder is read (a worktree's files stay put); repair, Finish and recovery send no link.
- **Apple events sent quietly** (`apps::send_link_quietly`, `kAEDoNotPromptForUserConsent`): never ask; they report "would need consent" instead.
